**핵심 규칙(불변)**: 의존은 **아래로만**(L2 도메인 → L0/L1). **도메인끼리·도메인→어댑터 직접 import 금지** — 융합은 **L1 백본(어댑터·workbook·registry·gsheet) 경유**. 조립(L3 pipeline)이 순서·전달을 오케스트레이션. (ARCHITECTURE §2·DOMAIN_DESIGN §3·PLATFORM_INTEGRATION §7)

**계층 요약** (4단):
- **L0 플랫폼(공유·가장 안정)**: `config`·`appconfig`·`apppaths`·`credstore`·`browser(+human_*)`·`session_*`·`wing_session`·`gsheet_api`·`gsheet` + **플랫폼 인증 관문(어댑터 세션)**.
- **L1 데이터 백본(공유)**: 조회 프리미티브(`collector`·`rank` + **어댑터 읽기/쓰기**) · 저장(`workbook*`·`gsheet_index/stats`·`pipeline_gsheet`) · 입력/원장(`input_list`·`registry_*`·`product_match`·`report`·`keyword_store`).
- **L2 도메인(개별·레인)**: D1~D10(§3).
- **L3 조립·표현**: `pipeline(+_sales/_ranks/_process/_paths/_gsheet)` · `ui/app_qt`·`ui/app`.

## 2. End-to-End 프로세스 흐름

각 단계 = **입력 → 처리 → 출력 · 담당 도메인 · 플랫폼 · 읽기/쓰기 · 자동/수동**. (상세는 각 SSOT 참조)

| # | 단계 | 입력 → 처리 → 출력 | 도메인 | 플랫폼 | 읽기/쓰기 | 자동/수동 | 상태 |
|---|---|---|---|---|---|---|---|
| 1 | **판매처·계정 등록** | 판매처·사업자·계정ID·비번(가림)·위탁상태 → 운영대장 계정관리(08-1) 저장 → 셀독원장 반영 | D8/L0 | 공통 | 쓰기(원장) | 수동(사람 입력) | 🆕입력화면·✅원장 |
| 2 | **상품 등록(온라인)** | 상품 스펙(제목·옵션·가격·이미지) → dry-run 미리보기→승인→어댑터 쓰기→원장 기록 | **D3** | 플랫폼별 | **쓰기**(§5.4) | 반자동(사람 승인) | 🆕 고위험 |
| 2' | **상품 등록(관리대장)** | 관리상품 16칸+키워드 → 운영대장 관리상품(01-2) 저장 | D4 | — | 쓰기(원장) | 수동 | 🆕 |
| 3 | **배치 수집** | 세션/토큰 → 야간 ① 흐름에 스테이지로 수집(판매·정산·문의·순위) → 백본 적재 + `_raw`·신선도 | D1·D8·D10 | 플랫폼별 | 읽기 | 자동(야간 단일 순차) | 🟡 일부 ✅ |
| 4 | **분석** | 수집본(판매·방문·노출·순위) → AI 키워드 선정·순위 진단·지표 집계 | **D1** | 쿠팡(+확장) | 읽기 | 자동(야간)/수동 | ✅ |
| 4' | **소싱** | 시드 키워드/카테고리 → 수요(검색량)·경쟁(1P 신호)·마진 → 후보 랭킹표 | **D2** | 쿠팡·네이버 | 읽기 | 수동(발굴 실행) | 🆕 저위험 |
| 5 | **상품 관리(변경)** | 재고·가격·판매상태 조회(수집본) + 변경 → dry-run→승인→어댑터 쓰기→원장 | **D4** | 플랫폼별 | 읽기+**쓰기**(§5.4) | 반자동 | 🟡 조회✅·변경🆕 |
| 6 | **CS(문의)** | 문의 수집/수동입력 → 상태(접수→진행→완료/보류)·응대 이력 → 통계 | **D10** | 쿠팡(+확장) | 읽기(+답변쓰기=미결) | 수동(1단계)/자동(2단계) | 🆕 |
| 7 | **정산 ①플랫폼** | 정산·매출·수수료 자료 수집/업로드 → 지급일·실지급·불변식 계산·검증 | **D8**(①) | 플랫폼별 | 읽기 | 자동(주1회)/수동 업로드 | 🟡 1단계✅·2단계🆕 |
| 8 | **정산 ②계약** | ①실지급 누적 + 계약 조건(계약 원장) + 관리 기간 → 달성률·잔액·회사 수익 몫 | **D8**(②) | 회사 단일 | 읽기+쓰기(계약 원장) | 반자동(계약 입력) | 🆕 3단계 |
| 9 | **정산 ③채권자** | ②회사 수익 몫 누적 → (법률→소유자 규칙) 상환 배분 → 채권/상환 원장(가림·별도파일) | **D8**(③) | 회사 단일 | 쓰기(원장·무인 금지) | 수동(사람 승인·감사) | 🆕 법률 민감 |
| 10 | **통계·출력** | 전 도메인 결과 → 사업자별 시트·계정목록·통계 마스터·구글시트 집계 | **D9** | 공통 | 읽기+쓰기(출력) | 자동 | ✅ |

> 현행 전체실행(야간 `--auto`) = **①반자동 판매수집(로그인) → ②키워드 선정(offscreen 없음) → ③반자동 순위**. 배치 수집 레이어는 이 흐름에 **스테이지로 얹는다**(새 병렬 실행 아님·PLATFORM_INTEGRATION §3.1). 정산·문의 수집은 로그인 세션 여는 ① 안에서 같은 세션으로 당겨오는 게 효율적.

```
D7 이미지 ──(산출물 경로/키)──▶ D3 등록
D2 소싱 ──(채택→등록 연계·백본 경유)──▶ D3 등록 ──(vid 부여)──▶ D1/D9 연결
D8 ①플랫폼 정산 ──(실지급 누적)──▶ ②계약 정산 ──(회사 수익 몫)──▶ ③채권자 정산   [단방향·역류 금지]
D10 문의 ──(계정+vid)──▶ D9 통계(CS량 융합 가능)
```

**연결 키(이미 확립·DOMAIN_DESIGN §4.2)**: `vendorItemId`(vid·불변 앵커)·`productId`·계정ID·사업자명 + (멀티플랫폼) `platform_id`. 도메인은 이 키로 서로의 백본 데이터를 **참조**(직접 호출 아님).

**핵심 선행 관계**:
- **계정(D8) → 상품(D4) → 분석(D1) → 통계(D9)**: 계정이 있어야 상품, 상품 vid가 있어야 지표·순위·통계.
- **①→②→③ 정산 단방향**(SETTLEMENT_MODEL §2·R3): ③이 ①②를, ②가 ①을 변경하지 않음. 감사·되돌림은 각 층 원장 내부.
- **소싱(D2) → 등록(D3)**: 후보 채택 후 등록, 등록으로 vid 부여되면 D1/D9 백본에 편입.
- **②계약 정산 입력 = 관리 기간**(셀독등록원장 `managed_between`·과거 계정 포함).
- **수집본이 조회의 선행**: 화면 조회는 수집본만 읽음(실시간 호출 아님·T4) → 수집(ingest)이 조회보다 앞선다.

## 5. 자동(배치·야간) vs 수동(사람 승인·쓰기) 경계

### 5.1 런타임 병렬 금지 (멀티플랫폼에서도 불변·PLATFORM_INTEGRATION §3.2)
- **쿠팡**: 단일 브라우저(sync playwright 스레드당 1개)·단일 위탁계정·Akamai → **계정 순차**. 로그인·rank 동시 open 금지.
- **스마트스토어**: API(HTTP)여도 **단일 통계 마스터/구글시트 쓰기 + 운용 PC 1대 쓰기**(R2④) 때문에 **여전히 야간 단일 순차**. 플랫폼 간 동시 실행도 금지.
- **즉 개발은 병렬(레인), 실행은 야간 단일 순차·라이브 한 번에 한 세션**(PARALLEL_DEV).

### 5.2 자동(무인) 허용 경계
| 작업 | 무인 허용 | 근거 |
|---|---|---|
| 판매·방문·노출·순위·재고 **수집**(읽기) | ✅ 자동(야간 ①~③) | 읽기 전용·기존 검증 완주 |
| 정산 ①수집(읽기·주1회) | ✅ 제안(요일 가드=월요일) | D8 §2.5 (최종 소유자) |
| 그로스/회사보유 재고 **역기록** | ✅ 자동 | 기존 운용 |
| 통계·구글시트 미러링(출력) | ✅ 자동 | 기존 D9 |
| CS 문의 수집(읽기·2단계) | 조건부(경로 확인·소유자 승인 후) | D10 §9 |

### 5.3 수동(사람 승인) 강제 경계 — **쓰기 안전 규약 §5.4** (DOMAIN_DESIGN §5.4·PLATFORM_INTEGRATION §5.1·확정)
현재 전 코드가 **읽기 전용**. 플랫폼 쓰기(상품 등록 D3·가격/재고 변경 D4·CS 답변 D10) 도입 시 **강제 4단계**:
1. **dry-run 미리보기**(무엇이 바뀌는지·현재값 vs 변경값·영향 상품/옵션). 이때만 어댑터로 현재값 실시간 재조회.
2. **사람 승인 게이트**(UI 확인·무인 자동 쓰기 금지).
3. **실행**(어댑터 쓰기 호출).
4. **원장 기록**(변경 전/후·실행자·시각·플랫폼 응답 append·멱등키/PENDING→COMMITTED).

- 위탁계정·Akamai·실운영 사고 위험 → **초기엔 반자동(사람 확인 필수)**. 폴백 최소화([[no-silent-fallback-principle]]).
- **③채권자 상환 기록 = 무인 절대 금지**(사람 승인·감사·법률 민감). ②계약 원장 쓰기도 쓰기 안전 규약(무인 금지). ①수집만 읽기(무인 가능).

## 7. 범위 경계 · 멀티플랫폼 확장 지점

### 7.1 범위 밖 = 샵마인(상용·확정 T3·[[app-scope-no-orders-shopmine]])
| 영역 | 담당 | 비고 |
|---|---|---|
| **주문**(발주·취소·구매고객 응대) | ⛔ 샵마인 | D5 범위밖·화면/메뉴 만들지 않음 |
| **배송**(출고·송장·배송상태) | ⛔ 샵마인 | D6 범위밖. 단 재고 반출(쿠팡→회사) 역흐름은 별도 검토 |
| **클레임**(반품·교환·환불 처리) | ⛔ 샵마인 | 처리는 샵마인 |
| 주문 데이터 기반 통계(취소·반품률 등) | ⛔ 기본 제외 | 필요 시 소유자에게 먼저 확인 |

- **CS 애매 경계**: 고객 문의가 주문/배송/반품 관련이면 성격은 CS(D10 접수·상태·이력만 기록) but **처리는 샵마인으로 넘김**(제안·D10 §1.3·미결 Q5).
- 수집·쓰기 어댑터에 **주문/배송 엔드포인트를 넣지 않는다**(PLATFORM_INTEGRATION §1.2).

### 7.2 멀티플랫폼 확장 지점 (PLATFORM_INTEGRATION §2.1·§2.5)
- **어댑터 추상화**: `PlatformAdapter` 프로토콜 + `platform/registry`(어댑터 레지스트리)만 열어두면 새 플랫폼 = **새 어댑터 모듈 1개 + DTO 정규화**만 추가.
- **정규화 지점**: 플랫폼 응답 → 공통 DTO(`ProductDTO`·`SalesRowDTO`·`SettlementRowDTO`·`InquiryDTO`)로 어댑터가 변환. 도메인은 DTO만 본다 → 플랫폼 추가 시 도메인 코드 불변.
- **정산 멀티플랫폼**: 정규화 부담은 **①플랫폼 정산 안에만** 가둠(②③은 회사 기준 단일·SETTLEMENT_MODEL §5). `payout.py` POLICY는 쿠팡 전용 → 스마트스토어 지급일 규칙이 오염시키지 않음.
- **선제 추상화 금지**(측정 기반): 스마트스토어 자료 실제 수령 전엔 공통 스키마/어댑터를 짓지 않고 **쿠팡 경로를 공통 스키마 모양으로만** 유지(SETTLEMENT_MODEL §5.2).
- v1 데이터 모델은 이미 멀티플랫폼 수용(IO_DEFINITION 「판매처」 선택값 = 쿠팡/스마트스토어/토스쇼핑/G마켓/당근).
