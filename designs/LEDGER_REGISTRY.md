# 설계: 셀독등록원장 (계정·상품 원장 + 변동이력)

> 상태: **설계 승인(2026-09-28) · 1단계(원장 생성·동기화) 구현 완료 — 오프라인 검증 통과, 라이브(실제 원장 구글시트) 미실행.**
> 작성 2026-09-28. 이 문서가 원장 기능의 SSOT다.
> 소유자 확정 사항은 각 절에 "(확정)"으로 표기.

---

## 0. 배경·목적

- 입력 원본 「셀독관리대장」(구글시트 `셀독리스트`)은 **매일 바뀐다**: 계정 추가·수정·삭제, 상품 추가·삭제·변경,
  취소선으로 거래 중지 표시, 줄 삭제. → 대장에는 **현재 위탁관리 중인 계정만** 남고 과거가 사라진다.
- 그러나 **월간·분기·반기별 정산/판매/매출 산정**에는 과거에 관리했던 계정·상품과 그 시점의 값이 필요하고,
  지금은 대장에 없는 과거 계정으로도 **로그인**해야 한다.
- 그래서 대장과 별도로 **「셀독등록원장」** 파일을 두고, 대장의 변경을 **지우지 않고 쌓는다**.
- (확정) **향후 앱은 셀독등록원장을 기준으로 실행한다.** 대장은 담당자가 편집하는 입력 창구로 남는다.

## 1. 파일·시트 구성 (확정: 시트 5개)

파일: **셀독등록원장** (구글시트, 별도 스프레드시트, 서비스계정 편집 권한)

| 시트 | 역할 | 편집 |
|---|---|---|
| **셀독원장** | 지금까지 등록된 **모든 계정·상품**(계정×상품 1줄). 관리중단도 지우지 않고 보인다 | 앱 자동 |
| **계정이력** | 계정 단위 항목 변경 | 앱 전용·추가만 |
| **상품이력** | 상품 추가·삭제(관리중단)·재개·상품명 변경 | 앱 전용·추가만 |
| **그로스이력** | 로켓그로스 입고 항목 변경 | 앱 전용·추가만 |
| **동기화기록** | 실행마다 비교 결과 요약 | 앱 전용·추가만 |

## 2. 셀독원장 열 정의

| 열 | 출처(대장 셀독리스트, 2026-09-20 백업 실측) | 단위 |
|---|---|---|
| 관리상태 | 앱 판정 (관리중 / 관리중단) | 줄 |
| 중단일 | 앱 판정 (관리중단된 날, 관리중이면 공란) | 줄 |
| 대표자명 | U 대표자명 | 계정 |
| 사업자명 | V 사업자명 | 계정 |
| 계정아이디 | W 계정아이디 | 계정 |
| 비밀번호 | X 비밀번호 | 계정 |
| 계약금 | Y 계약금 | 계정 |
| 체험단주체 | Z 체험단 주체 | 계정 |
| 상품명 | AA 상품명 (여러 줄이면 첫 줄 — 2026-09-27 규칙) | 상품 |
| 그로스 재고 | AD 그로스 재고 | 상품 |
| 그로스 요청수량 | AI 요청수량 | 상품 |
| 그로스 작업수량 | AJ 작업수량 | 상품 |
| 그로스 박스 | AK 박스 | 상품 |
| 그로스 파레트 | AL 파레트 | 상품 |
| 그로스 완료일자 | AM 완료일자 | 상품 |
| 그로스 출고일자 | AN 출고일자 | 상품 |
| 등록일 | 앱 (원장에 처음 들어온 날) | 줄 |
| 최종변경일 | 앱 (마지막으로 값이 바뀐 날) | 줄 |
| 쿠팡확인 | 앱 (쿠팡 실제 상태, §4-1) | 줄 |
| 쿠팡확인일 | 앱 (마지막으로 쿠팡에서 확인한 날) | 줄 |

- 열 위치는 고정 좌표가 아니라 **헤더 이름으로 찾는다**(기존 `config.IN_ALIASES_*` 방식 재사용). 대장 열이 옮겨져도 동작.
- 대장은 계정 정보(U~Z)가 **계정 첫 줄에만** 있다 → 원장은 **모든 줄에 채운다**(필터·정렬 가능하게).
- 서식: 관리중단 줄은 회색 글씨. 정렬 = 관리중 먼저 → 계정 → 상품. 관리상태 열에 필터.

## 3. 식별 기준·정규화

- **계정 = 계정아이디.** **상품 = 계정아이디 + 상품명.**
- 비교 전 정규화: 앞뒤 공백 제거·연속 공백 1칸·줄바꿈은 첫 줄만(상품명)·숫자 서식 통일(`90` = `90.0`).
  → 표기만 다른 것은 **변경으로 보지 않는다**(이력 잡음 방지).
- 상품명이 기호·공백뿐인 자리표시('--' 등)는 상품이 아님(기존 `_is_real_product_name` 규칙).

## 4. 동기화 규칙 (대장 → 원장)

실행 시(①②③ 시작 전 또는 버튼) 대장을 읽어 원장과 비교한다.

| 대장에서 일어난 일 | 원장 처리 | 기록 |
|---|---|---|
| 새 계정아이디 | 계정·상품 줄 추가, 등록일 | 계정이력 `신규계정` + 상품이력 `신규상품` |
| 새 상품(기존 계정) | 줄 추가 | 상품이력 `신규상품` |
| 계정 항목 값 변경 | 그 계정 모든 줄 갱신 | 계정이력 `수정` |
| 그로스 항목 값 변경 | 그 줄 갱신 | 그로스이력 `수정` |
| 그로스 재고 값 변경 | 그 줄 갱신 | **기록 안 함**(확정 — 앱이 매일 갱신·일자별 값은 통계 파일에 있음) |
| **계정 줄 전체 삭제 또는 계정 취소선** | 그 계정 **모든 줄** 관리중단 + 중단일 (확정) | 계정이력 `관리중단` |
| **상품 줄 삭제 또는 상품 취소선** | **그 줄만** 관리중단 + 중단일 (확정) | 상품이력 `관리중단` |
| 관리중단이던 계정/상품 재등장 | 관리중 복귀·중단일 비움 | 계정/상품이력 `재개` |
| 상품명 변경 의심 | **보류**(반영 안 함) | 상품이력 `상품명변경 ⚠확인필요` (§6) |
| 계정아이디 변경 의심 | **보류** | 계정이력 `계정아이디변경 ⚠확인필요` (§6) |

- 원장 줄은 **절대 삭제하지 않는다.**
- 대장 읽기 실패(403·시간초과 등)면 **동기화 전체 중단**(빈 대장으로 착각해 전부 관리중단 처리하는 사고 방지). 로그로 명시.
- 대장 계정 수가 직전 대비 급감(예: 30% 이상)하면 반영 전 경고·중단(대장 일부 유실 의심).

## 4-1. 대장 ↔ 쿠팡 불일치 (확정 2026-09-28)

원장은 **대장에 적힌 내용**을 기록한다. 담당자가 대장만 고치고 쿠팡에는 아직 반영하지 않은 경우를 구분하려고
**관리상태(대장 기준)** 옆에 **쿠팡확인·쿠팡확인일(쿠팡 기준)** 열을 둔다.

| 쿠팡확인 값 | 뜻 | 판정 근거 |
|---|---|---|
| 확인됨 | 대장과 쿠팡이 일치 | ①판매수집 로그인 성공 + 상품 매칭(vid) |
| 미등록 | 대장엔 있는데 쿠팡 상품과 매칭 안 됨 | 상품조회 미매칭 |
| 판매중(불일치) | 대장=관리중단인데 쿠팡=판매중/부분판매중 | 상품조회 productStatus (기존 판매상태 불일치 경고와 같은 판정) |
| 판매중지 | 쿠팡에서 판매중지(SUSPENDED 등) | productStatus |
| 로그인실패 | 로그인 차단·2차인증 등으로 확인 못 함 | classify_login blocked/otp 등 |
| 비밀번호불일치 | 원장(대장) 비밀번호로 로그인 오류 | classify_login = error |

- 채우는 시점 = ①판매수집으로 그 계정에 로그인했을 때. 로그인하지 않은 날은 이전 값·이전 확인일 유지.
- 쿠팡확인은 매일 바뀔 수 있어 **이력에 기록하지 않는다**(그로스 재고와 같은 방식).
- 동기화기록 시트에 **불일치 건수**(미등록·판매중(불일치)·비밀번호불일치)를 함께 기록하고 앱 로그로 알린다.
- 정산 숫자는 영향 없음: 판매·매출 금액은 쿠팡 실데이터(기간 지정 조회). 대장은 대상 계정·계약 정보만 좌우하며,
  대장을 늦게 고친 경우는 이력 `정정`으로 효력일을 실제 날짜로 소급.

**비밀번호 불일치 처리 = A안 (확정: 자동 재시도 없음)**
1. 원장 비밀번호로 로그인 오류(classify_login = error) → 기존 규칙대로 **즉시 중단·재시도 없음**
   (`LoginCredentialError`, 쿠팡 5회 오류 = 계정 잠금 방지). 쿠팡확인 = 비밀번호불일치.
2. 앱 알림: "비밀번호 불일치 — 쿠팡 비밀번호 변경 여부 확인 필요".
3. 앱에 **[이전 비밀번호로 1회 시도]** 버튼. 계정이력의 직전 비밀번호를 사용하며 **사람이 누를 때만** 1회 시도.
   - 성공 → 쿠팡확인 = 확인됨, 로그 "쿠팡은 아직 이전 비밀번호(대장만 변경됨)". 원장 값은 대장 기준 그대로 두고
     담당자에게 쿠팡 비밀번호 변경 또는 대장 되돌리기를 안내.
   - 실패 → 더 시도하지 않음. 담당자 확인 대상.
4. 자동 재시도(B안)는 채택하지 않음 — 기존 "비밀번호 1회 오류 = 재시도 금지" 정책 유지.

## 5. 이력 3종 공통 형식

| 열 | 설명 |
|---|---|
| 번호 | 시트별 1부터 빠짐없이 증가(끊기면 누가 지운 것 → 무결성 경고) |
| 실행번호 | 같은 비교에서 나온 변경 묶음(예 `R260928-1800`), 동기화기록과 연결 |
| 일시 | 앱이 변경을 발견한 시각 |
| 효력일 | 이 변경을 유효로 볼 날(기본=발견일·정정 시 소급 가능). **기간 산정은 이 값 기준** |
| 계정아이디 · 사업자명 | 기록 당시 값(나중 이름이 바뀌어도 이 줄은 그대로) |
| 상품명 | 상품·그로스이력만 |
| 변동유형 | 최초등록 / 신규계정·신규상품 / 수정 / 관리중단 / 재개 / 상품명변경·계정아이디변경 / 정정 |
| 항목 · 이전값 · 변경값 | |
| 출처 | 대장 시트·셀 위치(예 `셀독리스트 AJ15`, `대장에서 계정 삭제`) |
| 확인상태 · 확인자 · 확인일 | 확인필요 건만 사용 |

**항목 배정**

| 시트 | 추적 항목 |
|---|---|
| 계정이력 | 대표자명·사업자명·계정아이디·**비밀번호(원문, 확정)**·계약금·체험단주체·관리상태 |
| 상품이력 | 상품 신규·관리중단·재개·상품명 |
| 그로스이력 | 요청수량·작업수량·박스·파레트·완료일자·출고일자 |

- 원칙: **추가만**(수정·삭제 금지 — 잘못된 기록은 `정정` 줄을 새로 추가) · **앱만 기록**(시트 보호).
- 최신 줄이 위.

## 6. 이름 변경 확인 흐름

이름이 바뀌면 기계에는 "삭제 1 + 신규 1"로 보인다. 추측으로 합치면 다른 상품끼리 이력이 섞이므로 **자동 병합 금지**.

1. 같은 실행에서 한 쪽이 사라지고 비슷한 이름(기존 유사도 로직 재사용)이 생기면 `⚠확인필요`로 기록, 원장 반영 보류.
2. 담당자가 이력 시트의 **확인상태** 열(드롭다운: 승인/반려)에 입력 — 앱이 쓸 수 있는 유일한 사람 입력 칸.
3. 다음 실행 때 앱이 읽어 **승인** → 이력 이어 붙이고 이름 갱신 / **반려** → 옛 것 관리중단·새 것 신규.
   결정 결과는 새 줄(`확인완료`/`반려`)로 추가.
4. 7일 넘게 미처리면 경고 반복.

## 7. 과거 시점 복원 (정산·매출 산정용)

- `원장.as_of(날짜)`: 현재 원장에서 **효력일이 그 날짜보다 늦은 변경을 최신부터 되돌려** 그 날의 원장을 만든다.
- `원장.managed_between(시작, 끝)`: 계정·상품이력의 관리중단/재개로 관리 구간을 계산, **기간과 겹친 계정 전부** 반환
  (지금 관리중단이어도 포함).
- 예: 3분기(7/1~9/30) 대상 = 그 기간에 한 번이라도 관리중이던 계정 → 각 계정 9/30 시점 사업자명·계약금 → 로그인은
  **현재 비밀번호**.

## 8. 무결성·백업·권한

| 항목 | 방안 |

## 9. 비밀번호 정책 예외 (확정 2026-09-28 소유자)

- 원장과 계정이력에 **비밀번호 원문을 저장·이력 관리**한다(대장과 동일 수준).
