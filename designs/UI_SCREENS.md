> 시안(v32): https://claude.ai/artifact/UNnyH5Hs3SD33dH2QqGkXD · 보관 사본·생성 스크립트: `Downloads\커머스판로_시안_원본_20261003\` (`_시안_작업_안내.md`). 메뉴 SSOT=시안 A 보드(Sitemap). 진입 메모=[[handoff-design-mockup-261006]].
> 작성 2026-10-05 (H_ui 레인 · 소유자 요청 "IO 정의서 메뉴 ID 전체를 실제 앱 화면 구조로 조립").
> 목적: `designs/IO_DEFINITION.md`의 **메뉴 ID 전체**를 실제 앱의 **네비게이션·화면·카드**로 조립하고,
> 디자인 컨셉([[decision-design-concept-261003]])을 반영한 화면 구조·레이아웃·공통 컴포넌트·데이터 흐름을 정의한다.

> 정합: `designs/IO_DEFINITION.md`(칸 SSOT) · `docs/DOMAIN_DESIGN.md`(도메인) · `docs/ARCHITECTURE.md`(계층) · `designs/OPERATION_DATA_MODEL.md`(입력 스키마) · `docs/memory/decision-design-concept-261003.md`(디자인).

## 용어
- **화면**: 사용자가 보는 하나의 페이지(기존 QTabWidget 한 탭 = 한 화면).
- **메뉴 그룹**: 왼쪽 사이드바의 섹션(홈·상품·재고·…). 그 아래에 화면이 걸린다.
- **카드**: 흰 둥근 패널(한 화면 안 기능 묶음). 현 `_settings_tab`의 '파일·API 키'·'구글 시트 연동' 카드가 선례.
- **상태**: ✅기존 재사용 · 🟡부분(기존 일부+신규 카드) · 🆕신규.

## 3. 디자인 컨셉 적용 (QSS 방향성 — 구현 아님)

[[decision-design-concept-261003]] 원칙을 우리 데이터·업무에 맞춰 적용. **색=보라 하나**(강조·선택·주버튼·그래프), 경고만 빨강/주황.
Qt 적용 시 그림자는 성능 위해 **테두리 위주**(옅은 그림자 최소).

| 요소 | 컨셉 | Qt/QSS 방향 |
|---|---|---|
| 바탕 | 밝은 회색 | `QMainWindow { background:#f4f5f8 }` (현 `#e3e9f1` 교체 방향) |
| 카드 | 흰·둥근 모서리·얇은 테두리·옅은 그림자 | `border-radius:12px; border:1px solid #e6e8ee; background:#fff` |
| 강조색 | 보라 하나 | 토큰 `--accent:#6d4aff`(선택 탭·주버튼·그래프 채움) |
| 사이드바 | 흰·섹션 제목+아이콘+배지+하단 사용자 | 좌측 `QFrameW` 220px·선택 항목 보라 좌측바+연보라 배경 |
| 상단 바 | 경로+큰 제목+오른쪽 기간 알약+새로고침·마지막 수집 | `QLabel` 제목 20px bold + 우측 알약 버튼군 |
| 기간 알약 | 선택=보라 채움·비선택=회색 외곽 | `QPushButton[checkable] { border-radius:14px }` 선택 시 보라 |
| 큰 숫자 | 굵은 숫자 + 비교 배지(▲12%) | KPI 카드: 32px bold 숫자 + 작은 배지 |
| 막대 | 둥근 알약 막대·연한 트랙·선택만 진하게+말풍선 | 커스텀 `paintEvent` 또는 QSS 둥근 progressbar 응용 |
| 목록 | 상태 색 점+굵은 이름+회색 보조+우측 숫자 | `QListWidget`/`QTableView` delegate(상태 점=색 원) |
| 주 버튼 | 보라 알약 | `QPushButton#primary { background:#6d4aff; border-radius:16px; color:#fff }` |

- **토큰화**: QSS를 한 곳(`ui/theme_qt.py` 제안·신규)에 상수로 모아 색·반경·여백을 재사용. 현 app_qt 인라인 QSS를 점진 이관.
- **다크모드**: 현재 범위 밖(라이트만). 토큰 구조만 잡아 둠.

## 4. 기존 app_qt 탭과의 관계 · 점진 확장 순서

**현 app_qt**: `QTabWidget`(상단 탭 7개) + 하단 로그 스플리터. Mixin=`RegistryPanelMixin`·`StockPanelMixin`·`ProxyPanelMixin`.
**목표**: 왼쪽 사이드바 + 스택 페이지. **전체 재작성 금지** → 탭 내용(각 `_xxx_tab()` 반환 위젯)은 보존하고 **껍데기(shell)만 교체**.

| 현 탭 | 재사용 방식 | 목표 화면 |
|---|---|---|
| 설정 | ✅그대로(이미 설정 일원화·4링크·프록시·순위간격) | 설정 그룹(13-5·13-6) + 카드 분화(13-2·13-7·13-8·13-10 카드 추가) |
| 판매 분석(`_sales_tab`) | 🟡확장(통계 읽기 로직 유지) | 홈 대시보드 + 01-6 상품 상세 |
| 키워드 추천(`_kw_tab`) | ✅그대로 | 07-6 키워드 분석 |
| 순위 조회(`_rank_tab`) | ✅그대로 | 키워드·순위 그룹의 도구 화면 |
| 상세 이미지(`_images_tab`) | ✅그대로 | 상품 그룹의 도구 화면 |
| 전체 실행(`_collect_tab`) | ✅그대로(실행모드 3택·수집기간 유지) | 키워드·순위 그룹 '전체 실행' 또는 상단 공용 실행 |
| 정산(`_settlement_tab`) | 🟡분화(회사재고 카드·원장 카드 유지) | 08-3 변경 이력 + 04-1/04-6 정산 분리 |

**점진 확장 순서(껍데기 → 화면 채움)**:
1. **셸 도입(저위험)**: `QStackedWidget` + 왼쪽 `QListWidget` 사이드바 추가, **현 7개 탭 위젯을 그대로 페이지로 꽂음**(내용 0변경). QSS 토큰화 1차.
2. **설정 그룹 정리**: 기존 설정 카드 유지 + 13-2/13-7/13-8/13-10 카드를 설정 화면에 **추가**(미접촉 원칙).
3. **홈/상품 상세 분리**: `_sales_tab` 읽기 로직을 홈 대시보드(계정목록)와 01-6(상품 상세)로 **분기**(읽기 전용·안전).
4. **정산 분화**: 정산 탭을 08-3(원장)·04-1(정산 현황 업로드)·04-6(계약 정산)으로. 기존 원장/회사재고 카드 재사용.
5. **신규 입력 화면**: 08-1·11-3·11-4·01-1·01-2·03-x·06-x — OPERATION_DATA_MODEL 3단계 앱 배선과 **동반**(입력 스키마 확정 후).
6. **채권자·문의**: 권한 체계(§6) 선행 후 채권자(🔒), 문의(CS)는 D10 구현 착수 시.

> ⚠ 입력 화면(5)은 `input_list`가 운영대장 다중 시트를 읽도록 확장되는 **OPERATION_DATA_MODEL §11 3단계**에 의존. UI 단독 선행 불가 — 통합 세션과 동반.

## 6. 권한·민감 처리 UI (IO_DEFINITION 민감도 반영)

IO_DEFINITION 민감 분류 = **비밀**(화면·결과·로그 원문 금지) · **민감(가림)**(권한자만 원문).

| 민감 | 대상 칸 | 화면 규칙 |
|---|---|---|
| **비밀** | 계정 비밀번호 · 네이버/OpenAI/SA/공휴일 키 · 프록시 id:pw | 입력만 가능, **다시 안 보임**. `SecretField`=`●●●●●● [변경]`. 저장=credstore(DPAPI)·config는 평문 금지. 로그·결과에 원문 미출력. (예외=셀독등록원장 파일만 비번 원문 저장·화면엔 안 띄움) |
| **민감(가림)** | 사업자등록번호 · 정산계좌 · 수탁자 정보 · 채권자 이름/연락처/상환계좌 | 기본 **가림**(`123-**-*****`). **권한자(대표·정산담당)만 [원문 보기]** → 보일 때 **열람 기록**(누가·언제). 채권자 그룹은 비권한자에게 사이드바에서 숨김/잠금. |
| 일반 | 그 외 | 제약 없음 |

- **채권자(12-x)**: R2② = **파일 분리 + 대표/정산담당만 원문 + 화면 가림 + 열람 기록**. 상환 **배분 계산 결과는 참고 표시**만(배분 기준은 법률 검토 후 소유자 결정·앱은 계산/기록/감사). [[business-context-consignment-creditors]].
- **권한 모델(제안·미결)**: 현 앱은 단일 사용자(운용 PC 1대). 역할(대표·정산담당·일반)은 **설정의 로컬 플래그**로 시작(네트워크 인증 아님) — §8 미결.

## 8. 갭·리스크·미결

- ✅ **범위밖 확인**: 주문(D5)·배송(D6)·클레임 화면 **없음**([[app-scope-no-orders-shopmine]]). 사이드바·메뉴 ID에 미포함.
- 🟡 **문의(CS·D10)**: 입력 칸 0(향후). 사이드바 자리만 두고 화면 보류(쿠팡 문의 수집 경로 미확인).
- **UI 선행 불가 영역**: 신규 입력 화면(08-1·11-x·01-x·03-x·06-x)은 `input_list` 다중 시트 확장(OPERATION_DATA_MODEL 3단계)에 의존 → **통합 세션과 동반**, UI 단독 구현 금지.
- **네비 전환 리스크**: 상단 탭 → 좌 사이드바는 shell 교체라 저위험이나, **현 로그 스플리터·탭별 실행 버튼·`_on_tab_changed` 배선**(로그 가시성)이 사이드바 전환 이벤트로 바뀜 → 핀/시뮬 먼저. 현 7탭 동작 보존 확인 후 진행.
- **권한 모델 미결**: 역할(대표·정산담당·일반)·열람 기록 저장 위치·채권자 숨김 방식 = 소유자 결정 필요(단일 PC 로컬 플래그로 시작 제안).
- **디자인 컨셉 전면 적용 보류**: [[decision-design-concept-261003]] "앱 적용 보류" — QSS 토큰화는 가능하나 전면 리스타일은 소유자 승인 후.

**구현 우선순위(제안·기존 재사용 우선)**: ①shell+QSS 토큰(저위험·내용 0변경) → ②설정 카드 보강 → ③홈/상품 상세 읽기 분리 → ④정산 분화(원장 재사용) → ⑤신규 입력 화면(스키마 동반) → ⑥채권자(권한 선행)·문의(D10).

## 시안(Design 캔버스) 반영 지시 — H_ui 레인 (2026-10-05·통합 세션 작성)
> 통합 세션이 시안 "커머스 판로 화면 시안"(claude.ai Design 캔버스·114파일)을 **직접 편집하지 않는다**(시안 소유·맥락=H_ui 레인·블라인드 편집 시 충돌/일관성 위험). 아래를 **H_ui가 시안에 반영**한다. 소유자 2026-10-05 "디자인에도 모두 반영" 지시의 이행 명세.

**반영할 구조 변경(이번 세션 확정):**
1. **멀티플랫폼**: 플랫폼 = 쿠팡 + 스마트스토어. **v1 실질=쿠팡 우선**, 스마트스토어는 화면상 **'준비중/보류' 배지**(선택은 두되 비활성)로 표기(U1 보류). 계정·상품·판매·정산·문의 화면에 플랫폼 구분(배지/필터).
2. **샵마인 범위밖 유지**: 주문·배송·클레임 화면은 **만들지 않음**(사이드바·메뉴 제외). 단 **문의(CS)는 포함**(D10).
3. **신규/변경 도메인 화면**:
   - **D3 상품 등록**(01-2): 등록 폼 + 쓰기 안전 플로우(입력→검증→미리보기 dry-run→사람 승인→실행→결과) 시각화. 무인 자동 등록 없음.
   - **D4 상품 변경/삭제**(01-1): 조회(수집본)+수정, 변경/삭제도 승인 플로우. 소프트삭제(판매중지) 기본·하드삭제 2중확인 UI.
   - **D10 문의/CS**(**05 문의/리뷰관리**·v3.3): 목록/상세·응대·상태(접수→진행→보류→완료). 1단계=수동 트래커. 고객 연락처=가림.
