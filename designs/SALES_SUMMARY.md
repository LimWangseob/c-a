# 통합 판매현황 설계 (SALES_SUMMARY) — 2026-10-15 · 소유자 확정 사항 반영

## 1. 목적·확정 요구 (소유자 2026-10-15)
- **값**: 계정별·상품별 **판매수량·판매금액**, **윙 / 로켓그로스 구분**.
- **행**: 계정 → 상품(옵션 합산). 계정 소계·전체 합계.
- **기간 보기**: **월 · 주 · 전일**(주 = 월~일).
- **대상**: **위탁계정 전체**(관리대장 계정 + 정산 계정 파일의 계정).
- **위치**: 결과 파일(통계 마스터 xlsx + 결과 구글시트) **첫 번째 시트 `통합판매현황`** — 기존 시트는 한 칸씩 오른쪽.
- **갱신**: 매일 배치(18:00 무인·전체실행)로 다시 계산해 시트 통째 교체.
- **앱 조회**: 월/주/일·기간·계정 선택 조회 탭(4단계).

## 2. 원천 — 판매분석(주문 기준), 정산과 섞지 않음
- 판매분석 데이터 API `vi-detail-search`(`collector.fetch_sales_details(page, from, to)`) = 옵션(vid)별 판매금액(totalGmv)·
  판매수량·주문·구분(NORMAL=윙·RFM=로켓그로스)·상품명. **아무 기간이나 한 번에 조회**(기간 합계 = 하루 조회 합 — D-060 실측).
- 정산 파일은 매출인식일(구매확정 후) 기준이라 판매현황과 기준이 다름 → 쓰지 않음.

## 3. 저장 — 두 갈래
| 저장 | 파일 | 키 | 채우는 때 |
|---|---|---|---|
| 일별(있음·D-056) | `output/판매분석_일별/{계정ID}.json` | `YYYY-MM-DD` | 매일 ① 하루치(D-1) |
| **기간별(신규)** | `output/판매분석_기간/{계정ID}.json` | `M:YYYY-MM` · `W:YYYY-MM-DD`(그 주 월요일) | 매일: 이번 달·이번 주 누계 다시 조회 / 지난 달·지난 주 첫 마감 조회 / **처음 한 번 소급**(2026-01~지난 달·최근 주) |
- 기간 값은 쿠팡이 준 합계를 그대로 저장(일별을 더해 만들지 않음) → 로그인 실패한 날이 있어도 다음 날 기간 조회가 메움.
- 기록마다 `수집` 시각·`조회기간`·옵션별 {상품, 옵션, 구분, 판매금액, 판매수량, 주문}. 원자적 저장(임시 파일 → 바꿔 끼움).
- 저장 안 된 기간 = **'미수집'**(0 과 구분).

## 4. 집계 모듈 `sales_summary.py`(신규·순수 로직)
- 입력: 위 두 저장 + 계정 표시명(대표자-사업자-계정ID).
- 출력 행: (계정, 상품, 구분) → {전일, 주 N개, 월 1월~이번 달} × (수량, 금액) · 계정 소계 · 전체 합계.
- 상품 = 판매분석 상품명(옵션 합산). 같은 상품이 윙·로켓그로스 둘 다면 두 줄.

## 5. 결과 파일 첫 시트 `통합판매현황`
- 엑셀: `create_sheet('통합판매현황', 0)` → '계정 목록'·사업자 시트 한 칸씩 오른쪽. 구글: 시트 만들고 index 0 으로 이동.
- **특수 시트로 등록**(사업자 시트로 오인 금지): `workbook_common._SPECIAL_SHEETS`·`OutputWorkbook._reindex` 건너뜀 목록·
  구글 미러(push_statistics) 사업자 목록 제외·구글→마스터 복원 때 제거(`_strip_gsheet_index_tab` 와 같은 방식)·
  계정 삭제 정리 대상 아님.
- **배치 = 세로 3구역(소유자 2026-10-15 선택)**: [1. 전일] 계정·상품·구분·수량·금액 → [2. 주간(월~일) 최근 8주(이번 주 누계 포함)] → [3. 월별 1월~이번 달(누계)] — 각 구역 맨 위 전체 합계·계정마다 소계. 주·월 칸 = 수량·금액 두 칸.
- 매번 **통째로 다시 그림**(값·서식). 머리말 = 기준일·마지막 갱신·출처(판매분석·주문 기준)·미수집 계정 수.

## 6. 매일 배치
1. ① 판매수집: 계정마다 하루치(있음) + **기간 조회**(이번 달·이번 주·막 끝난 달/주·처음 소급) — 같은 로그인 세션·API 조회만.
2. ① 끝 → `sales_summary` 계산 → 첫 시트 다시 그림 → 저장 → 결과 구글시트 반영(기존 push 흐름에 시트 1개 추가).
3. 정산 계정 중 관리대장에 없는 계정 = 정산 자동 수집(watch)이 로그인한 김에 같은 조회(3단계·정산 세션과 순서 맞춤).

## 8. 위험·회귀 방지
- 새 시트가 사업자 시트로 오인 → 미러링·삭제 정리·색인 오류(1순위) → 5절 등록 + 시뮬·정밀 렌더 검증 시나리오.
- 조회 부하: 계정당 매일 +2~4회 API 조회(로그인 추가 없음)·처음 소급 약 15회 1회성.
