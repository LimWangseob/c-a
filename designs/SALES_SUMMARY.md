# 통합 판매현황 설계 (SALES_SUMMARY) — 2026-10-15 · 2026-10-21 대시보드 개편(D-094) 반영

## 1. 목적·확정 요구 (소유자 2026-10-15)
- **값**: 계정별·상품별 **판매수량·판매금액**, **윙 / 로켓그로스 구분**.
- **행**: 계정 → 상품(옵션 합산). 계정 소계·전체 합계.
- **기간 보기**: **월 · 주 · 전일**(주 = 월~일).
- **대상**: **위탁계정 전체**(관리대장 계정 + 정산 계정 파일의 계정). ⚠ 2026-10-21(D-094)부터 **집계 기준 = 관리 상품**(결과 사업자 시트 블록의 VID = 관리대장 상품·판매중지 블록 포함) → 결과 파일에 없는 계정·상품은 빠짐(§5-1).
- **위치**: 결과 파일(통계 마스터 xlsx + 결과 구글시트) **첫 번째 시트 `통합판매현황`** — 기존 시트는 한 칸씩 오른쪽.
- **갱신**: 매일 배치(18:00 무인·전체실행)로 다시 계산해 시트 통째 교체.
- **앱 조회**: 월/주/일·기간·계정 선택 조회 탭(4단계).

## 2. 원천 — 판매분석(주문 기준), 정산과 섞지 않음
- 판매분석 데이터 API `vi-detail-search`(`collector.fetch_sales_details(page, from, to)`) = 옵션(vid)별 판매금액(totalGmv)·
  판매수량·주문·구분(NORMAL=윙·RFM=로켓그로스)·상품명. **아무 기간이나 한 번에 조회**(기간 합계 = 하루 조회 합 — D-060 실측).
- 정산 파일은 매출인식일(구매확정 후) 기준이라 판매현황과 기준이 다름 → 쓰지 않음.

## 3. 저장 — 두 갈래
| 저장 | 파일 | 키 | 채우는 때 |
|---|---|---|---|
| 일별(있음·D-056) | `output/판매분석_일별/{계정ID}.json` | `YYYY-MM-DD` | 매일 ① 하루치(D-1) + **소급·빠진 날 보충**(D-094: 2026-04-01~어제, 최근부터 거꾸로·계정당 하루 최대 30일) |
| **기간별(신규)** | `output/판매분석_기간/{계정ID}.json` | `M:YYYY-MM` · `W:YYYY-MM-DD`(그 주 월요일) | 매일: 이번 달·이번 주 누계 다시 조회 / 지난 달·지난 주 첫 마감 조회 / **처음 한 번 소급**(2026-01~지난 달·최근 주) |
- 기간 값은 쿠팡이 준 합계를 그대로 저장(일별을 더해 만들지 않음) → 로그인 실패한 날이 있어도 다음 날 기간 조회가 메움.
- 기록마다 `수집` 시각·`조회기간`·옵션별 {상품, 옵션, 구분, 판매금액, 판매수량, 주문}. 원자적 저장(임시 파일 → 바꿔 끼움).
- 저장 안 된 기간 = **'미수집'**(0 과 구분).
- **일별 소급(D-094)**: `sales_summary.plan_backfill`(순수) → `pipeline_sales._record_sales_backfill`(① 같은 로그인 세션·
  `fetch_sales_details(page, d, d)` 하루씩). 이미 있는 날은 다시 조회 안 함 · 조회 사이 1~2.5초 · 실패면 그 계정 소급 멈춤
  (다음 실행이 이어서·비치명·로그) · '하루 최대 30일' = 그날 수집 시각이 찍힌 기록 수를 빼고 계산(재실행해도 넘지 않음).

## 4. 집계 모듈 `sales_summary.py`(상세표·소급 계획) · `sales_dashboard.py`(대시보드) — 순수 로직
- 입력: 위 두 저장(`scope` 로 관리 상품 VID 만 거름) + 계정 표시명(사업자 (계정ID)).
- 상세표 행: (계정, 상품, 구분) → 일별 최근 31일 × (수량, 금액) · 계정 소계 · 전체 합계.
- 대시보드 계정 하나의 기간 값 = 그 기간 일별이 **모두 있으면 일별 합**, 아니면 쿠팡 기간 합계(조회기간이 정확히 같은 것),
  둘 다 없으면 미수집(합계에서 빼고 개수 표시). 증감 % = 두 기간 **모두 받은 계정끼리**.
- 상품 = 판매분석 상품명(옵션 합산). 같은 상품이 윙·로켓그로스 둘 다면 두 줄.

## 6. 매일 배치
1. ① 판매수집: 계정마다 하루치(있음) + **기간 조회**(이번 달·이번 주·막 끝난 달/주·처음 소급) + **일별 소급·빠진 날 보충**(D-094) — 같은 로그인 세션·API 조회만.
2. ① 끝 → `sales_summary` 계산 → 첫 시트 다시 그림 → 저장 → 결과 구글시트 반영(기존 push 흐름에 시트 1개 추가).

- 새 시트가 사업자 시트로 오인 → 미러링·삭제 정리·색인 오류(1순위) → 5절 등록 + 시뮬·정밀 렌더 검증 시나리오.

  끝난 뒤엔 빠진 날만(보통 0회). 로그인 실패한 날은 다음 성공 실행이 자동 보충.
