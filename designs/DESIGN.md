- 비번은 공유 파일·출력·git 어디에도 쓰지 않는다. 계정 매칭 키 = `계정아이디`(입력 파일과 동일).

### 2.3 출력 — 생성 워크북 "상품별 노출 및 판매 현황"

도구가 입력 파일에서 **상품 행을 자동 시드**해 생성/갱신. 관리대장 `시트8` 스키마를 준용하되,
**계정 식별 컬럼을 추가**한다(같은 상품명이 여러 계정에 있을 수 있어 계정별 분리 필요).

| col | 헤더 | 용도 |
|---|---|---|
| A | 사업자명 | 계정 구분 키 (같은 상품명 계정별 분리) |
| B | 상품명 | 상품 블록 시작(빈 행은 직전 상품 소속) |

**상품 블록 구성(옵션 단위):**
- **노출순위** = **키워드별 × 옵션별** 1행 (키워드로 묶고 그 아래 옵션별 순위). 키워드 1회 검색으로 옵션들 순위 동시 산출.

**이어쓰기/신규(확정):** 실행 시작 시 기존 출력 파일이 있으면 **"이어서 기록할지"를 사용자에게 묻는다**.

- 새로 만들기 → 새 타임스탬프 파일 생성
**실패 표기(확정):** 로그인 실패 / 상품 미발견 / 검색 미노출 셀은 **공란**으로 둔다.

## 4. 로그인·세션 정책 (🔒 고정 — 변경 금지, 2026-09-05 라이브 검증)

> 이 절은 **정책으로 고정**한다. 아래 방식(실제 Chrome 자동입력 + 세션 영속)만 허용하며,
> §4.6의 금지 방식(HTTP 위장 로그인 등)으로 **되돌리지 말 것**. 코드가 이 절과 어긋나면 코드가 틀린 것이다.

### 4.1 원칙 (허용/금지 — 절대)
- ✅ **실제 Google Chrome + CDP(`WingBrowser`) 만으로 로그인**한다. 계정별 **영속 프로필**(`data/profiles/{계정ID}`)을 재사용한다.
- ✅ **자동입력**: 저장된 ID/비번을 로그인 폼에 자동 채우고 제출(`autofill_login`). 로그인 폼은 **xauth.coupang.com Keycloak 표준 폼**.
- ⛔ **지문 위조(UA/sec-ch-ua/Sec-Fetch 위장)·JA3/TLS 조작·Akamai `_abck` 재생 등 봇탐지 우회 금지.**
- ⛔ **`requests` 등 비브라우저 HTTP 로 Keycloak 폼-POST 로그인 금지**(§4.6). 실제로도 Akamai 차단으로 불가.
- ⛔ **2차 인증(휴대폰 인증번호)·CAPTCHA 는 도구가 풀지 않는다.** 사람이 창에서 처리(수동).
- 계정 **순차 처리 + 랜덤 지연.** 자격증명은 credstore(DPAPI) 밖으로 복사·로그·출력 금지.

### 4.2 로그인 완료 판정 (🔒 고정)
`WingBrowser.authenticated()` = **윙 대시보드 URL 도달(xauth/sso 아님) AND `KEYCLOAK_IDENTITY` 쿠키** — **둘 다** 만족.
- `seller-uid` 쿠키는 로그인 폼 단계에도 있어 **단독 판정 금지**(과거 오판 버그). URL 단독 판정도 금지(전환 중 transient).
- 세션이 실제 수집에 유효한지의 **궁극 판정은 `discover()`의 데이터 로드 성공**(만료면 실패→그 계정만 건너뜀).

### 4.3 로그인 상태머신 (계정 1개, `_login_and_discover`)
프로필을 재사용해 **창을 숨긴 채(offscreen)** 연다. 순서:
1. `goto(WING_URL)` → `authenticated()` **참이면 로그인 생략**(창 한 번도 안 뜸, 세션 재사용).
2. 거짓이면 **숨긴 채 자동입력**(`autofill_login`) 후 `wait_for_login`으로 대기.
3. `wait_for_login`이 화면을 **분류(`classify_login`)**: `success`/`error`/`blocked`/`akamai`/`otp`/`form`/`transition`.
   - `success` → 완료(True).
   - `error`(#input-error: 비번오류·계정잠금·90일휴면·OTP5회잠금) → **2회 확인 후 즉시 중단 + 증거 스냅샷**(자동 재시도 금지 = 계정잠금 방지).
   - `blocked`(Akamai Access Denied)·`akamai`·`otp`·`form 지속` → **사람 조작 필요**: 이때만 `on_need_user`로 **창을 예고 후 표시**(`show()`), 사람이 2차인증/직접 로그인.
4. 완료 후 **다시 숨김**(`hide()`) → 같은 세션에서 즉시 `discover()`.
- **창 표시 원칙(🔒):** 기본 숨김. **자동입력만으로 되면 창이 전혀 안 뜬다.** 2차인증 등 사람이 꼭 필요할 때만, **로그로 미리 안내한 뒤** 표시(갑작스러운 창 금지).

### 4.4 세션 영속·재사용·킵얼라이브 (🔒 고정)
- 로그인 성공 세션의 **3요소(WebSessionId·PCID·OAuthTokenRequestState) + 쿠키(_abck 포함)** 를 `SessionStore`(계정별 JSON, **DPAPI 암호화**)에 영속. 복원만으로 재로그인·2차인증을 건너뛴다.
- 생존검증 = `wing_session.is_alive`(`winglayout/bell/notification/find` 응답 "OK", **로그인된 브라우저 컨텍스트로만**).
- **세션 킵얼라이브**(선택, `session_keepalive.KeepAlive`): 앱이 켜진 동안 주기적으로 **숨긴 실제 Chrome으로 대시보드만 방문**해 세션을 살려둔다. **로그인 아님**(비번·2차인증·창 없음). 만료 계정은 로그인 시도 안 함. 전체 실행 중엔 자동 일시정지.

### 4.5 브라우저 안전장치 (🔒 고정 — 과거 버그 재발 금지)
- **잔여 Chrome 자동 정리**: 실행 직전 그 프로필을 쓰는 잔여 Chrome 만 종료(`_kill_profile_chrome`). 안 하면 프로필 잠금→디버깅 포트 미개방으로 실패.
- **포트**: `port=None`→`_free_port()`(로그인마다 빈 포트). `_connect_cdp` 6회 재시도. 포트 미개방 시 명확한 안내.
- **프로세스 정리**: `__exit__`→`_kill_tree()`(좀비 Chrome 방지).
- **복원창 억제** 플래그, 로그인 창은 `_center_pos`(표시할 때만).
- **중첩 금지(🔒)**: Playwright sync 는 한 스레드에 인스턴스 1개만 허용 → **rank_browser(순위용)를 로그인 브라우저와 동시에 열지 않는다.** 로그인 브라우저가 닫힌 뒤 계정마다 순위 브라우저를 별도로 연다.

### 4.6 ⛔ 금지·거부된 대안 (도입 금지)
- **HTTP 폼-POST 로그인(`http_login.py` 방식)**: `requests`로 Keycloak `login-actions/authenticate` 에 위장 헤더로 제출 + `_abck` 재생. **정책 위반(지문위조)이며, 라이브에서 실제 Chrome 제출조차 Akamai Access Denied(2026-09-03)** 였으므로 순수 HTTP 는 더 확실히 차단됨 → **기술적으로도 불가.** 파일이 남아 있어도 파이프라인에 연결하지 말 것.
- **offscreen 자동 순위검색(공개 SERP 직접 fetch/네비게이션)**: 라이브 실증(2026-09-15) 같은 warm IP에서 **0/237 전멸**(응답 23~59s→cooldown 2회 초과 당일중지). 실효성 없음 + IP만 태움 → **폐기.** 쿠팡 순위는 **반자동(visible 자동타이핑)만**(§5.2). `_backfill_ranks`/`_measure_unfilled_once`는 **사문화**(코드 잔존하나 `skip_ranks`·`keywords_off` 가드로 어느 실행에서도 미호출). ②키워드 선정의 **노출측정**(offscreen 공개검색으로 실노출 재기)도 전체실행에서 제외(단 쿠팡 자동완성=연관검색어는 유지 — full 검색이 아니라 가벼운 추천어).
- ShopMine 실행·의존, 세션 프로세스메모리 덤프.

### 4.7 검증된 사실 (라이브)
- 2026-09-05: **자동입력 로그인이 창 없이(숨김) + 2차인증 없이 성공** 확인(`✅ 로그인 완료`). 판매상품 없는 계정은 `판매분석 데이터 없음 — 정상`으로 처리(오류 아님).
- 2차인증은 **위치/환경 기반 조건부(step-up)** — 신뢰 환경은 없이 통과, 낯선 환경은 요구(그때만 창 표시). 인증번호 5회 오류 시 계정 잠금 → 자동 재시도 금지(§4.3 error 즉시중단).

### 4.8 검색어·로그인 입력 = 사람 타이핑(붙여넣기 금지, 차단 회피 — 🔒 2026-09-13 실측 고정)

> **원인(실측):** 쿠팡 Akamai는 **붙여넣기/즉시 채움**(value setter·`fill` = `isTrusted=false` input, keydown 없음)을
> 짧은 쿼리로 감지해 **차단**하고, **실제 키보드로 한 글자씩** 친 신뢰 키이벤트 입력만 통과시킨다.
> 그래서 **쿠팡 검색어(③ 자동·반자동)와 로그인 입력을 모두 사람 타이핑으로 통일**한다.
> 구현: `human_typing.type_focused` (← `rank.human_type_query` ← ③ 검색 경로·로그인 자동입력 공용). 지문위조 아님(정상 입력 재현).

- **한글 = CDP IME 자모 단위 조합**: 자모마다 `keyCode 229`(Process) keydown + **2벌식 자모→물리키 `code`** 부여 +
  `Input.imeSetComposition`(조합 텍스트 갱신 = `compositionupdate`, trusted) → 완성 시 `Input.insertText` 커밋(`compositionend`).
  실제 IME 타이핑과 같은 이벤트열(keydown 229 · compositionstart/update/end · input)을 낸다.
- **영문/숫자/기호 = `page.keyboard.type(ch)`**(신뢰 keydown/keypress/keyup).
- **글자(자모)마다 미세 랜덤 간격**(사람 리듬): `TYPE_KEY_DELAY_MIN~MAX`(0.14~0.38s, 평균 ~0.26s = 초중급 3~4타/초)
  \+ 확률적 **망설임**(`TYPE_HESITATE_PROB`=0.22 → +0.25~0.75s) + 드문 **긴 멈춤**(`TYPE_LONGPAUSE_PROB`=0.05 → +0.8~1.6s).
- **조합 커밋 단위 스위치**(`TYPE_JAMO_COMMIT_MODE`): `"eojeol"`(기본 — 어절 전체를 한 조합으로 이어 끝에 1회 커밋 →
  `compositionend`[isTrusted=false, CDP 한계] 빈도↓) vs `"syllable"`(음절마다 커밋 = 실제 IME 구조에 가까우나 compositionend[F] 다수).
  탐지 로직 미지 → **핫스팟 A/B 비교용** 스위치(값 조정은 config 수동).
- **입력 후 실행(Enter) 전 사람 멈춤**(`config.type_dwell` = 글자수×`TYPE_DWELL_PER_CHAR_SEC`(1.0) + `TYPE_DWELL_BASE_SEC`(2.0)
  = '글자수+2초'): 채우자마자 제출=봇 패턴 회피(사용자 관찰).
- **폴백 안전**: `TYPE_JAMO_IME=True`(자모 IME) → 값 검증 실패 시 음절 단위 신뢰 키입력 → 그래도 실패면 URL 폴백([rank.human_type_query]).
  compositionend만 isTrusted=false(CDP 한계), 자모 keydown·compositionupdate는 trusted. 한글 keydown이 막히면 이 CDP IME가 유일 경로.
- 관련 커밋(구현 순): `69ae85b`(붙여넣기 폐지→타이핑) → `ed1665c`(CDP IME 자모조합·로그인 동일) → `7165852`(초중급 속도·조합 keydown 물리키 code) → `aee1b9d`(어절 단위 커밋) → `70426e3`(어절/음절 커밋 스위치).

## 5. 파이프라인

### 5.1 Q1 — 판매분석 수집 (계정별)

**리포트 입도(확인됨):** 상품별=상품별이나 **기간 합계**, 기간별=일자별이나 **전상품 합계**.
∴ "상품별 × 일자별"은 어느 리포트에도 없음 → **상품별 리포트를 "하루 단위 기간"으로 다운로드**하고 일자 반복.

1. 세션 확보 + 대상 검증(§4) → 판매분석 이동
2. 일자 `d`에 기간 `d~d` 설정 → **상품별 판매 리포트 다운로드**
3. 상품(옵션)별 `조회/판매량/방문자` 추출, **상품 단위 합산**(§8-C)
4. 입력 파일 `상품명` ↔ 리포트 상품 매칭
5. 출력 워크북의 해당 상품 지표 행 × 일자 `d` 컬럼 기록
6. (백필) 기간 내 모든 일자 반복
- 최적화: 내부 API가 상품+일자 동시 집계 지원 시 단일 호출로 대체(§8-A)

### 5.2 Q2 — 검색 순위 추적 (비로그인) — **🔒 반자동(visible 자동타이핑)만, offscreen 자동 폐기(2026-09-15 정책 고정)**

> **정책:** 쿠팡 순위 측정은 **보이는 신뢰 창에서 앱이 키워드를 한 글자씩 자동 타이핑+Enter**(autosubmit)하고
> 화면(SERP)만 읽어 순위를 산출한다(③ 반자동). **offscreen에서 SERP를 직접 fetch/네비게이션하는 자동 경로는
> 폐기**(§4.6). 근거=라이브 실증(2026-09-15): 같은 warm IP에서 **offscreen 자동 0/237 전멸(응답 23~59s→당일중지)
> vs visible 자동타이핑 237/237 완주**. Akamai는 "어떻게 검색하느냐(신뢰 키입력·실제 창)"에 민감하다.

1. 출력 워크북에서 (상품, 키워드) 로드 — **이미 채워진 순위 셀은 건너뜀**(중단 지점부터 이어서)
2. 보이는 창에서 키워드 **사람 타이핑(§4.8)+Enter** → SERP 읽기(우리가 URL fetch/네비를 하지 않아 차단이 안 생김)
3. **광고 제외**, 배송타입 구분 없이 **통합 오가닉 순번**, **vendorItemId 앵커로 내 상품 매칭**(vid 없으면 상품명 폴백)
4. (상품, 키워드) `노출순위` 셀 × **최신 일자 컬럼** 기록. 상한 밖이면 **"50위밖"**(사용자 결정: 50위까지만 유지·그 밖 추가검색 안 함, 차단/미측정은 공란=재측정). 매칭 시 **계약상품명을 정확 노출명으로 갱신**(vid 앵커라 이름 바뀌어도 시계열 키 안정).

**차단 회피·서킷브레이커(확정):**
- 검색 **사이** 사람속도 간격 `RANK_NAV_DELAY_MIN/MAX_SEC`(현재 45~75s, config.py만), **병렬 금지**.
- 차단 감지 시 **하드중단이 아니라 쿨다운-재개** `RANK_SEMI_COOLDOWN_SEC=1800`×`MAX=4`(초과 시 당일중단). `RANK_SEMI_AUTO_MAX_MISS=3` 연속 미감지=차단 판정.
- (옛 자동 경로 서킷브레이커 `RANK_COOLDOWN 900s·MAX2`는 백필 사문화로 현재 미사용.)

**전체실행 흐름(2026-09-15):** ①반자동 판매수집 → ②키워드 선정(**노출측정=offscreen 공개검색 없음**, 단 **쿠팡 자동완성=연관검색어는 사용**) → ③반자동 순위. **offscreen 전무.** UI `do_run_full` 조합(§0-0).

## 7. UI·배포 (확정)

- **데스크톱 GUI → 단일 실행파일(.exe)** 로 배포(PyInstaller). 파이썬 설치 불필요, 더블클릭 실행.

  3. **선택 실행 범위 지정**: 특정 계정 / 특정 상품 / 특정 키워드 (기본=전체)
  4. **검색 기간(from~to) 입력** (수동 실행)

  6. 실행 → **진행 로그·계정별 성공/실패·오류·CAPTCHA 대기 안내** 실시간 표시

  (a) 담당자가 **본인 관리 계정만** 담은 파일로 실행, (b) **1인이 전체 계정** 담은 파일로 실행 — 둘 다 지원.
- **선택 실행:** 입력 파일 범위 안에서 **특정 계정·상품·키워드만** 골라 실행 가능.

## 12. 라이브 분석 결과 — 확정 메커니즘 (2026-09-01)

쿠팡은 **Akamai 봇탐지**를 로그인과 데이터 API에 적용한다(`xauth.coupang.com/lLRNBebz/...`,
`wing.coupang.com/KoOcG/...` 텔레메트리). 이로 인한 확정 사항:

- **로그인은 반드시 사람이, 실제 Chrome에서.** Playwright가 '띄운' 브라우저는 webdriver 흔적으로 로그인 무한루프.
  → **실제 Chrome을 `--remote-debugging-port`로 구동(자동화/위장 플래그 없음) + 사람이 직접 로그인** = 통과 확인.
- **⚠️ 정정(현재 구현, §0 line 44):** 아래 `storage_state`/쿠키주입 서술은 **폐지**. 현재는 **계정별 영속 Chrome 프로필** + 로그인 세션 3요소(WebSessionId·PCID·OAuthTokenRequestState)+쿠키를 **`SessionStore`(계정별 JSON·DPAPI 암호화)** 에 영속·복원(`session_store.py`/`wing_session.py`). 아래 두 줄은 역사적 기록.
- **세션 저장(옛):** 로그인 후 `storage_state`(쿠키 32개)를 `session_{계정}.json`으로 저장.
- **수집은 headless 불가.** headless+쿠키는 페이지는 열리나 **데이터 API가 403**(Akamai). → **실제 Chrome(오프라인 창) + 사람이 로그인한 그 세션/프로필 재사용**으로 수집(쿠키 주입 새 브라우저는 API가 막힘).
- **재로그인:** 세션 만료 시에만 사람이 재로그인(쿠팡 세션은 하루내 만료 경향 [[coupang-session-short-lived]]).
- **2차 인증(폰):** 새 기기/위치 최초 로그인 시 쿠팡이 휴대폰 2차 인증을 요구할 수 있음. 수동 로그인이라
  사람이 인증코드 입력해 통과(자동화 무관). 익숙한 환경(사무실)에서는 안 뜰 수 있음. 세션 저장 후엔 재인증 불필요.
- 판매분석 URL: `wing.coupang.com/tenants/business-insight/sales-analysis`. 내부 API: `/tenants/rfm-ss/api/...`.
- 계정 검증 소스 후보(§8-F): `/tenants/wing-account/vendor/salesinfo`, 대시보드 상단.

**판매분석 다운로드(라이브 확정, wellbing1107):**
- 날짜 = URL 파라미터 `?start_date=YYYY-MM-DD&end_date=YYYY-MM-DD`.
- '엑셀 다운로드'(드롭다운, no_wait_after 클릭) → '상품별 판매 리포트' 클릭.
- 다운로드는 **비동기 blob**(`/fcc/download-manager/request-auto-download` → `check-downloadable` 폴링)이라
  Playwright `download` 이벤트로 안 잡힘 → **CDP `Page.setDownloadBehavior`로 폴더 지정 + 폴더 감시**로 수집(18초).
- 데이터 로드 보장: `vi-detail-search` 응답 대기 후 다운로드.
- **리포트 옵션ID = 검색 vendorItemId 확인** → 순위 정확매칭 자동화.
- **제약:** 쿠키 주입한 새 브라우저는 데이터 API가 Akamai에 막혀 UI 미로드 → **수집은 실제 사람이 로그인한 그 세션**에서만.
  ∴ 계정별로 사람이 로그인한 브라우저에서 collector+rank 를 돌린다(세션 재사용은 그 브라우저가 살아있는 동안).

## 10. 오류·검증·운영 정책 (확정)

- **오류 처리:** 로그인 실패·CAPTCHA·상품 미발견 등은 **로그 파일 + 화면**에 간단한 오류 내용을 표시하고
  **다음 대상으로 계속 진행**(전체 중단 안 함). 해당 셀은 공란.
- **진행 표시:** 계정·상품별 진행상황과 오류를 실시간 화면 표시 → 담당자가 별도 대응.
- **입력 검증:** 입력 파일에서 **필수 항목이 비면 오류**(상속 적용 후 판정).
  필수 = `계정아이디`, `상품명`, 그리고 검증용 `대표자명`/`사업자명` 중 최소 1개. 오류 대상은 보고 후 제외.
- **상품명 매칭 실패:** 자동 추정하지 않고 **미매칭으로 표기**(화면·로그) → 담당자 수동 대응.
- **부하 관리:** 요청 간 지연·순차 처리로 과도한 부하/차단 방지(속도보다 안전 우선).
- **검색 기준:** **PC(데스크톱) 기준** 순위. 모바일은 추후 별도 진행.
- **세션 만료:** 로컬 저장 ID/비번으로 자동 재생성(§4). 재생성도 실패하면 오류 표시 후 다음 대상 진행.

### 결정 완료 (참고)
- 실행=기간(from~to) 입력 → **독립 스냅샷**(누적 없음) / 수동 / 로그=파일
- 노출순위는 **오늘만** 측정 가능(과거 소급 불가) → 과거 일자 공란
- 실행 범위=입력 파일 계정 / 선택 실행(계정·상품·키워드)
- 파일명=`쿠팡데이타분석_yymmdd_시분초` / 실패·미노출=공란 / 같은 상품명=계정별 분리
- 노출순위=광고 제외 통합순위. **자동=50위까지(`RANK_SCAN_MAX=50`)·반자동=로드된 페이지 실측 등수(최대 300)**, 50위 밖은 "50위밖"(미노출 아님·사용자 결정 추가검색 안 함) / 광고성과=수집 안 함
- 순위 상품 매칭: 라이브 확보한 vendorItemId(앵커)로 정확 매칭·상품명 부분일치 폴백(구현 완료). vid 앵커라 노출명이 바뀌어도 시계열 키 안정.
