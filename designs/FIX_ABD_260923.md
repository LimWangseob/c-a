## A. 계정목록 링크 재작성

### 문제 정의
운용 결과 구글시트 `계정목록` C열 일부 링크가 옛 코드가 쓴 **자기참조**(`계정목록!A1` 상당)로 남아, 상품명을 눌러도 해당 사업자 통계 시트로 안 감. 현재 코드는 올바른 링크를 만들지만 **다시 써야** 반영됨.

### 설계 (택1 — 소유자 확정 필요)
- **A-1 (권장) 경량 재링크 도구 `tools/relink_index.py` 신설**
  - 입력: 결과 구글시트 출력 URL + 마스터 통계 xlsx(`쿠팡데이타분석_통계.xlsx`).
  - 동작: `GSheetClient` 연결 → `OutputWorkbook` 로드 → `roster_from_workbook`로 IndexRow 산출 → `sync_index` 1회 호출. **로그인·판매수집·순위 없음**(gsheet만 접근).
  - 근거: `sync_index`가 이미 링크 재작성+마케팅 E~G 보존을 보장(`gsheet_index.py:474~491`). 신규 로직 아님, 기존 함수 재사용(추가 아닌 재사용 원칙).
  - 장점: 전체 실행(수 시간) 없이 링크만 즉시 복구.
- **A-2 (대안) 조치 없음 — 재실행이 자동 복구**
  - 다음 ①②③/전체 실행의 `_push_gsheet`가 `sync_index`로 C열 자동 재작성. 별도 코드 0.
  - 단점: 실행을 기다려야 함(소유자가 "실행 끝나면"이라 한 이유).

### 안전장치 (공통)
- ⚠ **gsheet 동시접근 금지**: 다른 PC서 실행 중이면 그 실행의 `_push_gsheet`와 충돌. 실행 종료 확인 후에만.
- 마케팅 E~G·직원 키워드 **미접촉**(sync_index가 자동열 A·B·C·D·H만 씀 — 이미 보장).

### 검증
- 오프라인: `verify_gsheet_offline.py` t6(링크=`#gid={사업자gid}&range=A{헤더행}` 형식) 초록 유지.
- 실측: 도구 실행 후 시트 C열 표본 1~2개가 `#gid=<사업자 gid>&range=A<헤더행>`인지 확인(자기 gid 아님).

## B. 순위 간격 35~55 실측 확인

### 문제 정의
소유자 지시로 검색 간격을 45~75 → **35~55**로 하향(2026-09-23, 시간단축). **차단/쿨다운이 늘면 45~75로 되돌려야** 하는데, 확인 수단이 "실행 로그를 사람이 grep" 뿐. 자동화·가시성이 없음.

### 설계 (택1)
- **B-1 (권장) 종료 시 순위 요약 + 되돌림 권고 로그**
  - 순위 단계 종료 시 1줄 요약: `[순위요약] 검색 N건 · 쿨다운 C회 · 차단감지 K회 · 간격 35~55s`.
  - 쿨다운/차단이 **1회 이상**이면: `⚠ 차단 발생 — config.py RANK_NAV_DELAY를 45~75로 되돌리는 것을 권고`.
  - 구현 위치: 순위 반자동 루프(서킷브레이커 카운터가 이미 있는 지점)에서 카운터를 모아 종료 시 출력. **행동 불변**(로그만 추가·측정치 미변경).
  - 근거: 되돌림 판단을 로그 grep 없이 즉시 하게 함. 핀=`pin_login_ranks`에 요약줄 시나리오 추가.
- **B-2 (대안) 순수 검증 — 코드 변경 0**
  - 운용 PC의 다음 최신-코드 실행 로그를 받아 `쿨다운`/`차단` 카운트만 확인. 0이면 유지, >0이면 config 되돌림.
  - 이 저장소엔 로그 없음 → **운용 PC 로그 필요**(소유자 제공 시 즉시 분석).

### 검증
- B-1: `verify_offline`/`pin_login_ranks`에 "쿨다운>0 → 권고 문구 출력" 시나리오. 실 API 없이 결정적.
- 공통: 실측은 운용 PC 로그(차단/쿨다운 0 확인).

## D. '둘다' 리스팅 NORMAL 고유옵션 손실 (A-2 항목)

### 문제 정의
`products_from_vendor_inventory`가 '둘다' 리스팅에서 NORMAL 옵션을 **item_name 대조 없이 전부 제외**(`collector.py:715~718`). RFM전용 옵션 + NORMAL전용 옵션이 **한 리스팅에 혼재**하면 NORMAL전용 옵션의 지표가 사라짐.

### 안전판 수정 설계
```python
# collector.py products_from_vendor_inventory, kind == KIND_BOTH 분기
if kind == config.KIND_BOTH:
    rfm = [o for o in listing.options if o.registration_type == "RFM"]
    rfm_names = {(o.item_name or "").strip() for o in rfm}
    # RFM에 같은 item_name 짝이 있는 NORMAL만 중복으로 제외. 고유 NORMAL은 보존.
    keep = rfm + [o for o in listing.options
                  if o.registration_type != "RFM"
                  and (o.item_name or "").strip() not in rfm_names]
    dropped_norm += len(listing.options) - len(keep)
    opts = keep or listing.options
```
- **왜 안전한가(비회귀 논증)**: 현재 확인된 케이스(같은 옵션=NORMAL+RFM 동일 item_name)에선 NORMAL이 여전히 제외됨(= 기존과 동일·중복 vid 안 생김). 동작이 **바뀌는 경우는 오직** "RFM 짝 없는 NORMAL 고유옵션"뿐 — 그게 지금 누락되는 대상.

### ⚠ 라이브 게이트 (필수 — 근거 없는 수정 금지)
- **회귀 리스크**: NORMAL·RFM이 **같은 물리 옵션인데 item_name이 미세하게 다르면**(예: 공백·접미사), 위 로직이 그 NORMAL을 "고유"로 오판 → 제외 실패 → 중복 vid → 이중집계. 이건 실제 회귀.
- 따라서 적용 전 **라이브 실데이터로 2가지 확인**:
  1. '둘다' 리스팅에 **RFM전용+NORMAL전용 혼재가 실재**하는가? (없으면 이 수정은 헛수정 → 미적용)
  2. 같은 물리 옵션의 NORMAL/RFM **item_name이 정확히 일치**하는가? (미세 불일치면 매칭 키를 item_name 대신 다른 안정 필드로)
- 확인 도구: `tools/diag_inv_hidden.py` 확장 — 계정별 '둘다' 리스팅의 옵션을 (registration_type, item_name, vendor_item_id)로 덤프해 혼재/이름일치 육안 확인.
- **결론**: 코드 수정 자체는 준비하되 **라이브 확인 통과 전 커밋 금지**. 확인 안 되면 진단 도구만 커밋하고 수정은 보류.

### 검증
- 오프라인: `verify_offline[8]`에 혼합 리스팅 페이크(RFM전용+NORMAL전용) → 고유 NORMAL 보존·중복 NORMAL 제외 어서션 추가.
- 라이브: 위 게이트 2항목 확인 후 다계정 실행(수집 상품수·옵션수·재고 대조).
