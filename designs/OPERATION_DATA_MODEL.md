# 설계: 셀독 운영 데이터 모델 (물류입고~정산 전과정 파일·시트 구조)

> 상태: **설계 확정(2026-10-01, 소유자 결정 7종 + 후속 확정) · 미구축.** 이 문서가 운영 데이터 구조의 SSOT다.
> 목적: 물류입고 → 상품등록/관리 → 그로스입고 → 광고/마케팅 → 판매 → 정산 **전 과정을 계정·상품 키로 연결**해 체계적으로 관리.
> 정합: 기존 `designs/LEDGER_REGISTRY.md`(원장)·`designs/DOMAIN_DESIGN.md`·`designs/SETTLEMENT_MODULE.md`·`designs/GSHEET_UNIFIED.md`.
> 근거: 소유자 제공 3파일 실측(관리대장 109열·재고현황·통계) + 소유자 결정(이 문서 §0).

## 0. 소유자 확정 사항 (2026-10-01)

1. **상품 안정키 = 자체 상품코드(셀독코드) 신규 발번**(불변).
2. **재고↔상품 수동 매핑 1회 후 고정**(물류명 띄어쓰기 변동 대비·자동매칭 오매칭 방지).
3. **"삭제" 4종 = 상태+이력**(계정삭제·상품삭제·**대체교체 old→new 링크**·판매중지), 지우지 않고 보존(원장).
4. **계약 = 계정별·상품별**, 계약서 **원본 문서는 소유자 PC 보관**, 시트엔 **계약 내용(조건)만** 데이터.
5. **광고 = 주별 입력 + 월별 합산.**
6. **채널(셀독/당근/자사) = 재고 표시까지만**, 판매·정산은 쿠팡만(추후 확대 가능).
7. **파일 최소화 + 계정/상품 키 링크 네비게이션**(관련 시트·행 이동).
8. **상품코드 첫 자리 = A~Z 분류 슬롯**(의미 부여 가능·확장).
9. **서식 = 컬럼 자동 폭 + 계정/블럭 바탕색 구분**(시각 관리).
10. **구글시트 사용·비밀번호 평문 보관**(원장 예외 유지).
11. **상품별·계정별 업무일지** 추가.

## 1. 설계 원칙

- **역할 3분리(불가침)**: 사람 입력 / 앱 이력(원장·append) / 앱 출력(교체). 앱이 출력을 통째로 교체하므로 입력·이력과 **절대 한 파일에 섞지 않는다**(입력 유실·이력 훼손 방지).
- **안정 키**: 모든 시트는 `계정ID`·`상품코드`로 연결. 이름(물류/내부/노출)은 변해도 키는 불변.
- **지능키 금지**: 코드엔 **거의 안 바뀌는 분류 1자**까지만. 세부 카테고리 등 가변 속성은 **컬럼**으로(재분류 시 코드·링크 안 깨지게).
- **삭제=상태**: 물리 삭제 대신 상태+이력(원장).

## 2. 파일 구조 — 스프레드시트 4개

| # | 파일 | 역할·소유·주기 | 분리 이유 |
|---|---|---|---|
| **1** | **셀독 운영대장** | 사람 입력(셀독·마케팅)·수시 | 입력 통합 |
| **2** | **재고현황** | 물류팀·수시 | **비번 격리**(물류팀이 운영대장 비번 못 보게) + 운영대장이 링크·미러로 통합 뷰 |
| **3** | **셀독등록원장** | 앱 전용·이력(append) | 삭제분·비번·이력 백본 (이미 구현=LEDGER_REGISTRY) |
| **4** | **결과/정산** | 앱 출력(교체/주기) | 통계(매일)·정산(주1회) |

> 재고가 별도 파일(2)이면서도 운영대장에서 **상품코드로 링크 + 현재고 앱 미러**로 통합 뷰를 준다(결정 1 a·b 동시).

## 3. 상품코드 체계 — `[분류1자][입고YYMM]-[순번3]`

예: **`G2608-001`** = (G 분류)·2026년 8월 물류 최초 입고·1번

| 자리 | 의미 | 규칙 |
|---|---|---|
| 1자 **분류** | **A~Z 확장 분류 슬롯** | 별도 `분류코드` 매핑으로 의미 부여. 초기: `G`건기식·`P`공산품·`E`기타 (A·B·… 추후 할당) |
| 4자 **입고YYMM** | 물류 **최초 입고** 연월 | `2608` |
| 3자 **순번** | 분류+연월 내 일련 | `001`~ (초과 시 4자 확장) |

- **불변**: 상품명·계정·노출명·vid 변경과 무관. 대체교체 시 **새 코드 + `대체상품코드` old→new 링크**.
- **분류코드 매핑**은 운영대장 `분류코드` 참조 시트(코드 1자 ↔ 의미)로 둔다 — A~Z 의미를 여기서 관리(코드 자체는 불변).
- **세부 카테고리는 코드에 넣지 않고** `상품` 시트 `카테고리` 컬럼으로(필터·정렬·그룹·색상은 컬럼으로 달성).
- 물류품목(재고·1개)과 셀독상품(계정 리스팅·계정별)은 1:N 가능 → `상품` 시트에서 **상품코드 ↔ 물류명/바코드** 수동 매핑 1회 고정(결정 2).

## 4. 파일1 — 셀독 운영대장 (사람 입력·시트 구성)

- **열 그룹 3종**: `신원`(사업자명·상품(물류)명 등 왼쪽·초록 헤더) / `내용`(파란 헤더) / `코드`(상품코드·계정아이디·바코드·계약ID 등 **숨김**). 어두운 헤더=흰 글씨.
- **파생열 = 수식연동·잠금**(§4.9): 사업자명·상품(물류)명·현재고·그로스재고는 숨김키(상품코드·계정아이디)로 `INDEX/MATCH`. 원본 1곳 수정 → 관련 시트 자동 갱신. 파생·키 셀은 **잠금**(시트 보호), 원본만 편집 가능.
- 시트 순서: 대시보드 → 관리상품·재고·그로스입고·체험단·광고·업무일지·계정·계약·분류코드 → 정의·안내(맨 뒤).

### 4.1 `계정`
대표자명 · 사업자명 · **계정아이디**(사업자명·비밀번호 사이) · 비밀번호(평문) · 위탁상태(관리중/관리중단) · 관리시작일 · 중단일 · **판매가주체** · **리뷰비주체** · 비고
- 체험단주체 "판매가:계약자 / 리뷰비:계약자"를 **판매가주체·리뷰비주체 두 열로 분리**(항목5).

### 4.2 `계약` (계정별·상품별·다건)
사업자명 · **대표자명** · 상품명 · **계약서종류** · **계약일자** · 계약기간시작 · 계약기간종료 · 수탁자 · 수익배분 · 수익기준 · 계약금 · 계약단가 · 계약수량 · 계약금액 · 광고비부담 · 재고배송부담 · 정산시점 · 귀속기준일 · 특약 · 계약서위치 · 비고 · (숨김)계정아이디 · 상품코드 · 계약ID
- 계약서 **원본은 소유자 PC 보관**, 시트엔 조건만(`계약서위치`=Modusign ID 등). **계약서=계약조건 권위 소스** → 전환 시 사업자명 정확일치 보강·없으면 신규행(`CONTRACTS`).

### 4.3 `관리상품` (셀독 상품 = 계정의 쿠팡 리스팅)
사업자명(파생) · **상품(물류)명**(=내부명+물류명 일원화·**쿠팡 하이퍼링크**) · 노출상품명 · 카테고리 · 판매방식 · 계약단가 · 판매가 · **현재고**(파생) · **그로스재고** · 상품등록일 · **관리상태**(상품등록일 다음) · 비고 · (숨김)계정아이디 · 상품코드 · 바코드 · 대체상품코드
- 상품명+물류상품명을 **상품(물류)명 하나로 일원화**, 쿠팡 링크를 그 셀에(별도 상품url 열 폐지·항목1).

### 4.4 `그로스입고` (이력 누적)
사업자명(파생) · 상품(물류)명(파생) · 현재고(파생) · 그로스재고(파생) · 요청일자 · 요청수량 · 작업수량 · 박스 · 파레트 · 완료일자 · 출고일자 · 입고지 · 비고 · (숨김)상품코드
- 요청/완료/출고일자 **시간 제외**(날짜만).

### 4.5 `체험단`
사업자명(파생) · 상품(물류)명(파생) · 요청일 · 키워드 · 판매가 · 리뷰/택배 · 건수 · 신규/추가 · 견적서판매가 · 견적서리뷰/택배 · 밑작업 · 포토/텍스트 · 진행여부 · 완료일 · 효과 · 비고 · (숨김)계정아이디 · 상품코드 · 체험단ID

### 4.6 `광고` (주 입력·월 합산)
사업자명(파생) · 상품(물류)명(파생) · 연 · 월 · 주차 · 기간시작 · 기간종료 · 광고비 · 노출 · 클릭 · 전환 · 매출 · 비고 · (숨김)상품코드

### 4.7 `업무일지` (계정별·상품별 공용)
일자 · 사업자명(파생) · 상품(물류)명(파생) · 작성자 · 내용 · 후속조치 · 상태 · (숨김)계정아이디 · 상품코드
- 기존 날짜별 관리내용 컬럼·상품 히스토리 일원화. **구분 열 삭제**(항목4).

### 4.9 자동연동·서식 (항목8·9)
- **파생열 수식**: `=IFERROR(INDEX('<마스터>'!<반환열>, MATCH($<숨김키셀>, '<마스터>'!<키열>, 0)), "")`. 사업자명←계정, 상품(물류)명/그로스재고←관리상품, 현재고←재고.
- **셀 잠금**: 파생·숨김키=잠금, 원본(신원·내용)=해제, 시트 보호 발효 → 원본만 수정·파생은 자동.
- 숫자=원단위 정수 콤마(#,##0) 우측정렬, 날짜=YYYY-MM-DD(시간 없음), 컬럼 폭 자동, 계정별 8색 밴드.

### 4.8 `분류코드` (참조)
분류1자(A~Z) · 의미 · 비고 — 상품코드 1자 슬롯의 의미 사전.

## 5. 파일2 — 재고현황 (물류팀)
창고 · 구분 · 바코드 · **물류명** · 현재고 · 채널(셀독/당근/자사) · 갱신일
- 물류팀 편집·비번 격리. 운영대장 `상품`이 물류명/바코드로 **상품코드 매핑** + 앱이 현재고 **미러**(읽기).
- ⚠ 물류명 **띄어쓰기 변동** 주의 → 매핑은 상품코드 기준 수동 1회 고정(자동매칭 아님).

## 6. 파일3 — 셀독등록원장 (앱 전용·이력)
`designs/LEDGER_REGISTRY.md` 그대로. 셀독원장·계정이력·상품이력·그로스이력·동기화기록. **삭제 4종 상태·대체교체 old→new·비번 평문·기간 정산 대상.** 본 모델의 "삭제돼도 관리" 요구를 충족.

## 7. 파일4 — 결과/정산 (앱 출력)
- 통계: 계정목록 + 사업자별 지표(매일 교체·현 `쿠팡데이타분석_통계`).
- 정산: 지급일·금액·계약 대비 달성률(주1회·`SETTLEMENT_MODULE.md`, `계약` 시트 소비).
- **포맷 샘플**: `tools/build_result_sample.py`(계정목록·통계 블록·정산현황 예시, 실데이터 아님·앱이 실제 생성).

## 8. 링크 네비게이션 (결정 7)
- 전 시트의 `계정ID`·`상품코드` 셀 = **HYPERLINK**로 관련 시트·행 이동(현 통계 계정목록→사업자시트 `#gid&range` 방식 확장).
- 예: 재고 행 상품코드 → `상품` 행 / `상품` → `계약`·`그로스입고`·`체험단`·`광고`·`업무일지`·통계 상호 이동.

## 9. 서식 (결정 9·앱 적용)
- **컬럼 폭 자동**(내용 길이 맞춤) — 현 계정목록 자동폭 로직 재사용.
- **바탕색 구분**: 계정별 밴드색(사업자 기준 교대·현 GSHEET_UNIFIED §계정목록 8색 밴드 재사용) + **블럭(상품군) 구분색**(같은 상품군 동색). 시각적 관리.
- 사람 입력 시트도 앱이 주기적으로 서식 정규화(멱등)하되 **사람 입력 값은 미접촉**(현 마케팅 E~G 미접촉 원칙 준용).

## 10. 전 과정 흐름
```
물류입고   → [2]재고(물류명·바코드·현재고)
상품등록   → [1]상품(상품코드 발번·물류명→내부명→노출명·카테고리) + [3]원장 상품이력
그로스입고 → [1]그로스입고(요청·출고 이력) + [4]그로스재고 자동갱신(앱) + [3]그로스이력
광고/체험단 → [1]광고(주/월)·체험단
판매       → [4]통계(앱 매일: 노출·판매·방문·재고)
정산       → [4]정산(앱 주1회: 지급일·금액·계약 달성률) ← [1]계약 소비
업무일지   → [1]업무일지(계정/상품 전 과정 기록)
```

> **2단계 전환도구 구현(2026-10-01)**: `tools/build_operation_template.py`(빈 틀·신 스키마) + `tools/migrate_to_operation_ledger.py`(관리대장+재고 → 운영대장: 상품코드 발번·수식연동·셀잠금·계약서 보강·8색 밴드). 결과=검토용 DRAFT(`매핑검토` 시트). **현 앱 흐름 미접촉**(별도 도구).

## 11. 단계적 전환 계획 (현 앱 영향)
현 앱은 입력=관리대장(단일 109열)·출력=통계·백본=원장을 쓴다. 전환은 **입력 스키마 정규화**가 핵심이라 범위가 크다 → 단계적.
1. **1단계(구조 확정·빈 틀 생성)**: 운영대장 4파일·시트·컬럼·분류코드·링크 틀 생성(데이터 없이). 기존 흐름 미접촉.
2. **2단계(이관·매핑)**: 현 관리대장 109열 → 운영대장 시트로 이관 + 상품코드 발번 + 재고↔상품 수동 매핑 1회.
3. **3단계(앱 배선)**: `input_list`가 운영대장 다중 시트를 읽도록 확장(현 단일 시트 파싱 대체)·원장/통계/정산 연결·서식 적용. 레인=E(원장/정산)·F(구글시트)·G(워크북)·통합.
4. **4단계(정산·광고·업무일지 소비)**: 계약·광고·체험단을 정산/통계에 반영.
- ⚠ 각 단계 게이트(run_checks) 초록·행동 불변 원칙. 입력 스키마 변경은 `input_list`·`gsheet_index`·`workbook` 광범위 영향 → 핀 먼저.
