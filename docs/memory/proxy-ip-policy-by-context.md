**IP 정책 = 작업 맥락별로 정반대다 (혼동 금지 SSOT)**

"쿠팡은 1개 고정 IP로 신뢰를 쌓아야 차단이 준다"와 "순위는 회전해야 한다"는 **모순이 아니다. 서로 다른 작업 얘기다.**

## 로그인·판매수집(위탁계정) = 고정 IP
- 계정/세션(KEYCLOAK)이 **있다**. 신뢰의 주체 = 계정+IP의 **일관성**. 사무실 고정 IP = 평소 신뢰 환경 → 2차인증 면제([[login-2fa-location-based]]).
- IP를 바꾸면 = 계정 탈취 의심 → 밴·2차인증. **그래서 고정이 맞고, 이 원칙은 안 바뀐다.**

## 노출순위(③, 비로그인 공개검색) = 회전(sticky 여러 개)
- 계정이 **없다**(완전 익명). 쌓을 "계정 신뢰"가 애초에 없음. 남는 건 익명 IP의 평판·볼륨뿐.
- 지배 위험 = **한 IP에 자동검색이 누적되면 그 IP가 볼륨으로 플래그되는 번아웃.**
- **라이브 실측(2026-10-02, [[proxy-live-test-261002]])**: 고정 ISP(Decodo)=~7검색 뒤 영구차단(번아웃), 회전 주거용(DataImpulse)=통과. **측정이 증명.**

## 왜 혼동이 생겼나 (플립플롭 기록)
- **2026-10-01**(테스트 전 추론, [[proxy-integration-off-261001]]): 순위 프록시도 "회전 금지·고정 IP 화이트리스트" 권고 → **로그인용 "고정=신뢰" 논리를 계정 없는 순위에 잘못 옮긴 실수.**
- **2026-10-02**(라이브 실측): 그 추론이 반증됨 → 순위는 회전으로 교정. **추측 금지·실측 우선([[fix-from-real-evidence]]) 규칙대로 근거 교체.**

## 정확한 회전의 뜻 (오해 금지)
- ⛔ 매 요청 회전(순수 rotating) 아님 — SERP 리소스가 제각각 IP로 나가 불일치로 **더 차단**.
- ✅ **검색 1건 내내 IP 고정(sticky) + 번아웃 구간 넘길 때만 다른 sticky로 교체.** "검색 안에선 고정, 밖에선 교체" = 10-01의 맞는 직관(일관성)은 살리고 틀린 부분(영구 단일 IP)만 교정.

**Why:** 소유자가 "고정이 신뢰 아니냐"로 재질문 → 맥락 분리를 명확히 안 하면 매번 재논쟁.
**How to apply:** 프록시/IP 얘기 나오면 먼저 "로그인인가 순위인가"부터 구분. 로그인=고정, 순위=sticky 회전. 둘을 같은 규칙으로 묶지 말 것.
