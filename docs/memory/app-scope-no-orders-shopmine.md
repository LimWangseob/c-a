**소유자 결정(2026-10-02)**: 주문·배송·일부 CS(문의·CS메모)는 **샵마인 상용 프로그램**에서 한다 → 우리 앱에 **주문/배송/클레임/문의 기능 만들지 않음**. 쿠팡 WING 기능 중 **상품등록은 우리 앱에서**, 주문·배송은 안 함. 우리 앱이 보강할 것 = **관리·통계**: 판매 현황, 매출 현황(쿠팡 매출내역), 정산 현황, 미지급 정산, 상품관리(조회·분석·등록), 재고, 키워드·순위, 원장.

⚠**수정(소유자 2026-10-05)**: **문의(CS)는 앱에 포함**으로 변경 → 신규 **D10 문의/CS** 도메인(DOMAIN_DESIGN §1·§9 R5). **주문(D5)·배송(D6)·클레임은 여전히 샵마인 범위밖**.

⚠⚠**대폭 확장(소유자 2026-10-05, 2차)**: 통합앱을 **멀티플랫폼 통합 관리 앱**으로. **샵마인 = 주문·배송만**으로 축소, **상품·판매·정산·문의(CS)는 통합앱이 직접** 담당. 구체:
- **v1 플랫폼 = 쿠팡(WING) + 스마트스토어(네이버 커머스 API)**, 나머지(토스쇼핑·G마켓·당근)는 어댑터 확장 지점만. 🔒**스마트스토어 API 위탁접근 보류(소유자 2026-10-05·U1)** → v1 실질 타깃=쿠팡 우선, 스마트스토어 어댑터는 자리만·접근 방식 추후 재검토(위탁주 협의·라이브 선필요).
- **배치 수집 레이어**: 각 플랫폼의 문의·판매·정산 자료를 주기적으로 당겨 저장 → 앱은 **조회**(실시간 호출 아님).
- **쓰기(온라인 반영)**: 상품 **등록/변경/삭제** + **CS 답변**을 플랫폼에 실제 반영(§5.4 쓰기 안전 규약·위탁계정 밴 위험 고위험). ← D10 CS가 이제 **답변 쓰기 포함**(기존 '읽기 전용' 제안 수정).
- **정산 3층**: ①플랫폼 정산(위탁계정이 쿠팡/스마트스토어에서 받는 금액) ②계약 정산(커머스 판로↔위탁자) ③채권자 정산.
- 구현은 보류(설계만). SSOT=[[domain-design-elaboration-261005]]·designs/PLATFORM_INTEGRATION.md·SETTLEMENT_MODEL.md(작성 중).

**Why:** 샵마인을 이미 쓰기로 함(중복 개발 방지). 화면 시안 검토 중 샵마인 주문 화면·WING 화면을 참고로 보여줬다가 "전부 구현하면 안 됨"으로 범위를 그음.

**How to apply:**
- 설계 `docs/DOMAIN_DESIGN.md` 의 D5 주문·D6 배송(🆕 계획)은 **범위 밖**으로 봐야 함 — 문서 갱신은 통합 세션 소관(공유 파일). 새 기능 제안 시 주문·클레임 처리/조회를 넣지 말 것. **문의(CS)는 2026-10-05부로 범위 안(D10)** — 넣어도 됨(단 주문/배송 처리는 여전히 금지).
- 주문 데이터에 기대는 통계(취소·반품률 등)도 기본 제외 — 필요하면 소유자에게 먼저 물을 것.
- 상품등록(D3)은 우리 범위 — 쿠팡 쓰기 작업이라 미리보기→승인→실행→기록 규약.
- 홈 화면 시안(Design 캔버스 https://claude.ai/artifact/UNnyH5Hs3SD33dH2QqGkXD): 홈·상품관리·매출정산 3장 + 공통 메뉴, 주문 화면 삭제됨. 앱 적용은 보류 상태.
