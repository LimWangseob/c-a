**결정(소유자 2026-10-02)**: 운영 시스템 DB는 **구글시트로 시작**한다. 아래 **규칙 4가지**를 지킨다. **구현은 보류**(소유자: 아직 의견 수렴·설계 단계).

1. **돈·재고 기록 시트는 앱만 추가** — 정산 확정·채권 원장·상환·재고 이동은 앱(서비스계정)만 쓰고 사람은 보기 전용. 고칠 일은 '정정' 줄을 새로 추가+사유(셀독등록원장 방식).
2. **채권자 파일 분리** — 약 370명 연락처·계좌는 별도 스프레드시트, 공유는 대표·정산 담당만, 화면은 가림 표시.
3. **저장 부분 한 곳** — 앱의 읽기/쓰기를 한 모듈(저장 계층)에 모아, 나중에 DB로 옮길 때 그 부분만 교체.
4. **쓰기 담당 PC 하나** — 처음엔 운용 PC만 쓰기, 다른 PC는 보기·요청(지금 원장 잠금은 같은 PC 안에서만 유효).

**Why:** 구글시트는 무료·이미 연동·직원 익숙. 약점=동시 편집 잠금 없음·행 단위 권한 없음·수정 추적 약함·API 분당 한도 → 규칙으로 보완. 데이터 양은 문제 아님.
**How to apply:** 새 기능 설계 시 이 4규칙을 전제. **재판단 시점**=창고 바코드 다중 동시 입력·여러 PC 동시 쓰기 시작 → Cloud SQL(PostgreSQL 1코어 전용 월 약 10만 원 추정, 2026-09 기준 단가) 등으로 이전. 결정 기록(docs/DECISIONS.md)·설계 반영은 통합 세션에 요청함(2026-10-02). 관련=[[business-context-consignment-creditors]]·[[feature-ledger-registry]]
