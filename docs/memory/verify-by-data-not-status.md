앱/파이프라인 실행 결과가 "완료·성공"이라고 표시돼도 **무조건 정상으로 판단 금지**. 반드시 **산출된 데이터 자체를 분석**해 정당한 값이 나왔는지 확인한 뒤에만 정상처리로 판단한다.

**Why:** 성공 로그/완료 표시와 실제 데이터 정합은 별개. 로그인·수집이 "완료"여도 값이 공란·낡은값·오매칭·0·placeholder일 수 있음(실측 사례 다수: 낡은 판매중지 표기·검색링크 폴백·순위 공란 등). 소유자 강조(2026-09-28).

**How to apply:** output.zip 등 실행 결과 분석 시 — ①마스터/시트의 실제 셀 값(순위·판매·재고·pid·상태·링크)을 표본·전수로 열어 확인 ②원본 응답(_raw)과 대조해 값의 출처·정당성 검증 ③"완료 26개"류 로그만 보고 통과 판정 금지 ④공란·0·placeholder·낡은값·오매칭을 능동적으로 탐색 ⑤정당한 값이 실제로 산출됐을 때만 "정상처리"로 보고. [[fix-from-real-evidence]] [[analysis-request-no-code-change]]
