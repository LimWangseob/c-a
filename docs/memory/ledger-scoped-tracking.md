**2026-09-10 구현.** 추적 모델을 **discover 기반→대장(입력파일) 기반**으로 전환(DESIGN §2.1 "상품은 판매분석 제공"을 사용자 지시로 뒤집음).

**정책(사용자 확정):**
- 추적 대상 = **입력 대장의 상품(위탁 관리분)만**. 판매분석에 잡힌 그 외 등록상품은 관리대상 아니라 제외.
- 대장↔발견(등록) 상품은 **핵심 키워드 매칭**(대장명≠등록명). 매칭 시 **발견 노출제목으로 시트 표시**(B). 미매칭이어도 **대장명으로 추적**(A) — 판매지표·재고 공란, 키워드·순위는 대장명 기준.
- **판매중지 상품 제외**(대장 텍스트 마커 판매중지/중단/종료/불가; "판매부진"은 계속판매라 유지).
- 판매하다 중지→이전 통계 유지·이후 공란, 대장에서 사라지면 생성안함 = **대장스코핑 + carry_forward(추가전용) 로 자동 충족**(추가 코드 불필요).

**구현:**
- `product_match.py`(신설) `scope_to_ledger(ledger, discovered)→(추적목록, 매칭수)`. 매처: **대장명 괄호 안 전체제목**이 있으면 발견제목과 정확매칭(대장 형식=`내부코드명 (노출제목)`이 많음), 없으면 **브랜드(발견제목 60%+ 공통어) 제외 + 띄어쓰기 제거 부분일치 + 유일배정(1발견=1대장)**. 실측 65개중 37매칭, 오매칭 최소(웰빙곳간 16 정상 미매칭=휴면).
- `input_list.parse`: 판매중지 텍스트마커 제외(`_is_discontinued`), 취소선 제외는 [[input-ledger-format]] best-effort.
- `pipeline._login_and_discover`: 활동필터(조회/판매/방문>0) 제거 → `scope_to_ledger`로 교체.
- 재고: 매칭된 vid만 쓰므로 [[rank-blocked-placeholder-50]]식 페이지네이션 부담 감소(전량 재요청은 collector에 이미 반영).

**검증:** pyflakes·vulture 0, simulate_pipeline 8시나리오 전부 통과.

**정밀 매칭(2026-09-18, 오매칭 차단)**: 쿠팡 상품조회로는 위탁/직접 판매 구분 불가 → 대장이 유일 기준인데 대장명≠쿠팡명일 수 있어, 느슨한 옛 매칭(`sc≥2` 토큰합)이 **비관리(직접판매) 상품에 오매칭**돼 통계에 섞였음. `_assign` 정밀화: ①괄호 노출제목 정확일치 최우선 ②아니면 **대장 핵심어(IDF 최고 토큰)를 발견제목이 포함 + 재현율 ≥0.55(`_RECALL_MIN`) + 2등 마진 ≥0.15(`_MARGIN`)**만 매칭 ③미달=미매칭(공란, 오매칭보다 안전). 규격/수량 토큰(120정·600mg·88% 등 숫자+단위=`_SPEC`) 핵심어 제외, IDF 동점이면 긴 토큰을 핵심어로. `augment_unmatched`도 같은 게이트. 소유자 결정=**정밀 우선만**(대장 역기록=쿠팡 정확제목/vid 써주는 확인루프는 보류). 검증 verify_offline[11]. 한 번 vid 잡히면 vid 앵커 안정.
