소유자(2026-10-06, D8 정산 세션 끝): "빠른 응답도 좋지만 분석이 정확해야 돼. 도메인 세션간 분업도 잘 안되고 있어."

**Why(이번 세션에서 실제로 틀렸거나 엉킨 것):**
- 확인 없이 단정: "18:00 무인 실행이 이 노트북에서 같은 프로필을 쓴다"(실제 야간 실행은 운용 PC·노트북 단계기록 마지막 09-18) · "메인 폴더에 검증된 config.json·씨앗이 있다"(통합 세션 빌드 중 노트북 config 비어 있음 발견 → 설정 씨앗 제외).
- 실측 없는 추정치를 일정처럼 말함(26계정 수십 시간 — 계정 수 확인 전).
- 분업: D8 브랜치가 master보다 뒤처져 통합이 파일만 골라 병합 · DECISIONS·배포 요청을 여러 번 쪼개 보냄 · 같은 결정(exe/watch)을 소유자가 두 세션에서 받음 · 빌드 담당을 두고 세션 간 왕복.

**How to apply:**
- 보고·제안 전, 환경 사실(어느 PC·어느 폴더·파일 존재·설정 값)은 **직접 확인하고 확인 방법을 적는다**. 확인 못 하면 "추정 — 확인 필요(무엇으로)"로 분리. 숫자 추정은 근거 데이터가 있을 때만.
- 작업 단위 시작 전 레인 브랜치를 master에 맞춘다(뒤처진 브랜치로 커밋 금지).
- 공유 파일·배포·DECISIONS 요청은 **작업 단위 끝에 한 번에**, 정확한 변경 명세로 통합 세션에 보낸다.
- 소유자 결정은 받은 세션이 즉시 통합 세션에 전달·기록 → 다른 세션은 같은 질문을 다시 하지 않는다.
- 다른 레인 파일(build·config 등)이 필요하면 착수 전에 담당을 정하고 시작(중간 왕복 금지).
