**사업 맥락(소유자 2026-10-02)**
- 회사는 **쿠팡 계정 위탁관리**를 한다. 판매 수익금 중 일부가 **회사 수익** → 정산 기능이 핵심(쿠팡 지급 → 회사 몫/위탁자 몫).
- 필요 기능(소유자 열거): 계정별 상품관리, 상품별 **체험단·광고 운영**, **수익률**, 정산·판매·매출, **상품 추천/분석**, **위탁자 CS + 고객 CS**, 전체 통계, **재고관리 + 최초 사입 상품 등록**, 회사 창고 입고 후 **실시간 추적·현황**.
- **특이점**: 회사가 파산 직전 — **정산 미지급자(투자자) 약 370명·300억 원 이상**을 관리하고 수익 일부로 **지속 상환**해야 함.

- **사업관리(소유자 2026-10-02 추가)**: 사업 종류가 여럿 — **셀독관리 · 위탁관리(쿠팡 계정 상품 관리 대행) · 광고 대행 · 상품위탁 판매** + 앞으로 추가 가능. → '사업 유형'을 모든 데이터(고객·계약·계정·상품·매출·수익)의 기본 꼬리표로 두고, 새 사업은 코드 수정 없이 유형+수익 규칙 등록으로 추가하는 구조가 맞음. **셀독관리 = 회사 자체 브랜드 상품 판매**(소유자 2026-10-02), 사업들이 "혼합되어 있음" → 한 쿠팡 계정 안에 셀독 브랜드 상품과 위탁 상품이 섞일 수 있다고 보고 **사업 꼬리표는 상품 단위**로 설계(계정 단위 아님). 셀독 상품은 **고객 계정에서도 판매**하고, 그 경우 **계정 주인 몫 = 판매액의 일정 비율**(소유자 2026-10-02 확정). 다른 사업별 수익 방식은 미확인.
- **DB 방향(소유자 2026-10-02)**: 구글시트로 하고 싶어 함 → Claude 권고 = 구글시트로 시작하되 ①돈·재고 이동 원장 시트는 앱(서비스계정)만 쓰고 사람은 보기 전용 ②채권자 파일은 따로·공유 최소 ③앱의 저장 부분을 한 곳에 모아 나중에 DB로 옮기기 쉽게 ④창고 동시 실시간 입력 시작 전에 다시 판단. (소유자 수용 여부 미정)
